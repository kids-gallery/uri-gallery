## 공통/모드별 책임
- store.ts: 작품/가족/원본 Blob·ID 소유. 변경 대상 아님. 기존 원본 14개 해시, 새 합성 PNG 해시 유지.
- spatialLayout.ts: 모드별 방 중심·통로·건축 solid·바닥과 스폰. 실제 형상·동선을 정의하며 단순 색 JSON이 아님.
- spatialNavigation.ts: ThreeMuseum 파생 충돌·이동. 렌더러 의존 없음.
- spatialScene.ts: layout의 기록에서 박스 벽/기둥/지붕/바닥과 camera solids 생성. scene 소유 geometry만 dispose, 공유 작품 texture는 dispose하지 않음.
- museum.ts: 작품 액자/명패/대표작·선택·나이 전시와 새 배치 접속. 원본 사진은 평면·전체 비율 유지.
- cameraRig.ts/engine.ts: 카메라 근평면·아바타 가림·입구·입력·선택/재생. scene 전환 전 현재 상태 확보, 새 공간 생성 성공 뒤 교체, 실패시 이전 공간 유지.
- WorldView.vue: 저장 성공 후 선택 표시, 실패시 복귀·재시도 안내. 패널 안 모든 입력은 월드로 전달하지 않음.

## 단계/산출물/통과 기준
1. 조사·UI 계약·고정 출처 → 위 파일과 라이선스 보존. 원격 코드 실행 없음.
2. 공통 기반 → PC/모바일 입구 카메라가 벽에 압축되지 않음; 가까우면 아바타가 작품을 가리지 않음. 일반/대표작 클릭은 playing 증가0, 명시적 재생만 증가. 패널 입력 시 이동0.
3. 클래식 구조 → 빈 중정과 순환이 평면/회색 화면으로 확인되고 모든 작품 stand에 도달 가능. 벽/기둥/받침대 관통0. 이를 먼저 실제 화면 확인한 후 확장 검증.
4. 나머지3모드 → 동일 눈높이/위치/화각 입구·작품·반대각도 및 회색모형, 전체 조감도. 색을 제거해도 실루엣/동선이 구분되어야 통과. 같은 상자 색 바꿈은 실패.
5. 전환/저장 → 4×2 옵션 왕복 후 ID/해시/이야기/대표작/나이 유지. 실패 주입 시 이전 장면/설정 복귀. 공유 texture 조기 dispose 및 scene 누수 검사.
6. 성능 → 먼저 동일 조건 CPU 프로파일로 입장 정지 원인 확인. rAF와 GPU 시간 별도. 기존 조건·임계값 완화 금지. 소프트웨어 렌더러는 GPU 성공 아님. 실제 휴대폰/가족 반응은 미검증.
7. own diff만 commit/push → 브랜치·원격 해시 확인. main·배포 금지.
