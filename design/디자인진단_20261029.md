# 디자인 진단(단계 1, 2026-10-29)

SD_02 17-20 디자인 시스템 작업의 단계 1이다. 화면을 고치지 않고 지금 상태만 잰다.

## 1. 어떻게 쟀나

- **대상.** 라우터(`web/src/router/index.ts`)의 화면 33개.
  - 보호자 2D 화면: Docker 개발 묶음(`localhost:9601`, 실제 API·DB, 시험 계정 둘)
  - 3D 세계: 오늘 커밋된 최신 3D 판(개인 판 개발 서버 `localhost:9501`)
- **폭과 상태.**
  - 모든 화면을 390px·1280px로 찍었다. 보통 상태, 키보드 포커스(Tab 3회), 첫 버튼에 마우스 올림을 함께 찍었다.
  - 데이터를 받는 화면 9개는 로딩(응답 4초 지연)과 오류(응답 503)도 찍었다.
  - 빈 화면은 아이·작품이 없는 계정으로 찍었다.
- **도구.**
  - `web/scripts/design_audit.py`: 캡처 234장과 자동 점검 값(`audit.json`)을 만든다. 단계 4가 끝난 뒤 같은 스크립트를 다시 돌려 확인한다.
  - 캡처 원본은 `.data/design-audit/20261029-before-3/`(git 제외)에 있다. 한눈에 보는 시트는 `design/진단_20261029/`에 있다(`sheet-390.jpg`, `sheet-1280.jpg`, `sheet-loading.jpg`, `sheet-error.jpg`).
- **판정 방법.** 자동 점검은 의심만 세고, 판정은 캡처를 보고 정했다. 표의 숫자는 캡처 번호다.
- **값 사용 현황.** `web/src` 아래 `.vue`·`.css`·스타일을 담은 `.ts`에서 셌다.

## 2. 가장 미완성처럼 보이게 만드는 원인 3개

1. **개발용 안내와 내부 용어가 화면에 그대로 나온다.**
   - 막힌 주 버튼 안에 "(비활성) - 이메일을 적어 주세요" 같은 글자가 붙어 흐리게 보인다. 가입·로그인 정보 찾기·비밀번호 재설정·초대·업로드·계정·운영 로그인·빈 작품 관리, 로그인의 카카오 버튼까지 9개 화면이다.
   - 처리 규칙의 게이트 용어 "막힘 / 사유 / 해제 주체"가 인증·가족 없음 화면과, 오류가 난 화면 6개에 나온다.
   - 3D 세계 첫 화면에 "테스트 계정으로 들어가기"가 있고, 운영 화면에는 `seed-…` 판 이름과 해시가 그대로 보인다.
   - 부모가 "지금 무엇을 하면 되는지"보다 "개발자가 남긴 설명"을 먼저 보게 된다.
2. **화면마다 시각 체계가 다르다.**
   - 한 서비스 안에 일곱 가지 모양이 섞여 있다.
     - 하늘과 신전 그림: 입장·견본·로그인·미술관
     - 분홍 상단바와 작은 알약 버튼: 앱 껍데기
     - 크림색 금 액자: 작품
     - 분홍 평면도: 전시실
     - 파스텔 초록 지도: 마을
     - 만화 곰: 캐릭터 만들기
     - 어두운 실사진 회랑: 회랑
   - 코드로 보면 2D 화면에 색 값 546종, 그림자 135종, 간격 197종, 모서리 44종, 글자 크기 22종이 직접 적혀 있다.
   - 토큰 파일(`styles/tokens.css`)은 있지만 값이 16개뿐이고, 그것도 거부된 파스텔 묶음(`--color-block-lime·lilac·pink·mint`)이다. 테마 파일도 `classic`·`paper`·`game`·`room` 네 개로 갈라져 있다.
3. **기다릴 때와 틀렸을 때의 화면이 비어 있거나 제각각이다.**
   - 로딩: 마을·목록·작품 관리·작품 상세·아이 관리·운영 상태는 빈 크림색 화면만 보인다. 미술관만 "미술관 문을 여는 중이에요"를 보여 준다.
   - 오류: 홈·마을은 쉬운 말 카드에 [다시 해 보기]가 있고, 나머지 6개는 게이트 상자에 [다시 하기]다.
   - 1280px: 가입·인증·찾기·재설정·초대·가족 없음·운영 로그인은 폼이 왼쪽에 좁게 붙고 화면 오른쪽 3분의 2가 비어, 덜 만든 것처럼 보인다.
