# 운영 관측·복구 실행 설계 (검토안)

상태: 설계 검토 중. 구현·배포·복구 완료를 뜻하지 않는다. 관련: #103~#113.

## 목표와 범위
서비스의 로그를 레벨별로 확인하고, 가족 데이터의 보존·접근 통제·장애 복구를 검증한다. 현재 main의 compose는 개발용 가짜 모델 및 Mailpit 설정이며 실제 운영 서버 상태는 확인하지 않았다. #41, #43, #44, #45의 진행 중인 검증을 재사용한다.

## 실행 순서
1. #103 로그 허용 목록과 개인정보 유출 경로 확인. Node 숫자 level/time과 Python 문자열 level/ts를 정규화한다. HTTP 5xx는 info 로그에도 있으므로 별도로 계산한다.
2. #104 Alloy → Loki → Grafana를 격리된 개발 환경에서 구성한다. app-api, model-api, worker, sweeper부터 수집하고 nginx·DB·메일 원문은 안전성이 확인될 때까지 수집하지 않는다. 운영자 인증과 내부망 제한을 적용한다. 요청/작업 ID는 고유값이므로 Loki 인덱스 라벨로 사용하지 않는다. 무로그와 수집 중단은 heartbeat로 구분한다.
3. #105 로그 회전, Loki 보관 삭제, 디스크 한도와 로그 전달 실패를 검증한다. 보관 7일은 결정되지 않은 제안이다.
4. #108 개발·시험·운영의 볼륨, DB, 비밀 및 접근 경계를 분리한다. 이미 초기화한 MariaDB의 비밀번호는 파일 교체만으로 변경된다고 가정하지 않는다.
5. #113 삭제·백업 만료 정책을 결정하고 #107 DB와 파일을 일관된 시점으로 백업해 격리 환경에 복원한다. 삭제 이력 재적용과 작업 상태 재개, 실제 시간과 파일 무결성을 확인한다.
6. #109 두 가족의 파일·작품·권한과 캐시를 시험한다. #110 격리 시험 볼륨에서 워커 종료·DB/파일 쓰기 실패·중복 처리·재시작을 시험한다. 시험 표본은 합성 데이터만 쓴다.
7. #106 기존 지표의 타입을 확인하고 큐 지연·워커 중단·수집 중단을 감지한다. 알림 수신과 외부 생존 감시는 별도 환경에서 검증한다. #111 배포 버전·설정·마이그레이션·롤백과 핵심 흐름을 기록하고 #112 비용·인수인계 기준을 실측한다.

## 완료 기준
각 이슈의 완료 기준과 해당 환경의 시험 결과를 증거로 남긴다. 가짜 모델을 통한 흐름 검증과 실제 모델 검증을 분리한다. 원본 사진, 비밀, 가족 식별 정보는 기록하지 않는다. 개인 정보 차단 시험, 복구 시험, 운영 권한 검증이 끝나지 않았다면 공개 운영 준비 완료로 표시하지 않는다.

## 미결정
로그 보관 기간·예산·알림 수신 채널·운영자 접근 방식·백업 위치·RPO/RTO·삭제 및 서비스 종료 정책은 책임자가 결정한다. 보관 정책 결정과 운영 서버 적용을 이 문서만으로 승인한 것으로 간주하지 않는다.

## 현재 확인과 한계
2026-11-03: main 기준 기존 pino/structlog 로그 및 `/metrics` 구현과 이슈를 검토했다. Docker 엔진에 연결되지 않아 구성 실행·장애 주입·복원 테스트는 하지 못했다. Grafana 대시보드와 운영 설정은 아직 구현하지 않았다.
