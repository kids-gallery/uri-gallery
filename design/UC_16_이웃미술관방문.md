# UseCase 명세 — #16 이웃 가족의 아이 미술관을 방문한다 (우리 아이 미술관, D40)

> 2026-09-30 이제민 결정 D40(REF). 화면 SD_02 §17-13 D·E·F, 데이터 SD_03 `family_neighbor` · `neighbor_invite` · `child` 캐릭터 칸, 계약 `/v1/town` · `/v1/neighbors*` · `/v1/visit/*`.

## 유스케이스 기술

| 항목 | 내용 |
|---|---|
| 주 액터 | 보호자(초대하는 가족 · 받는 가족 · 방문하는 가족) |
| 목적 | 서로 초대로 맺은 가족끼리 아이 미술관을 구경한다. 모르는 가족의 아이 정보는 드러내지 않는다 |
| 사전조건 | 두 가족 모두 로그인한 보호자가 있다 |
| 사후조건 | 이웃이 되면 서로의 마을 건물 문이 열리고, 끊으면 즉시 잠긴다 |
| 업무 규칙 | 방문자는 그림·별칭·제목·캐릭터·미술관 모양만 본다(나이·한마디·감상평·그린 날·원본·저장 없음) · 이웃 상한 30가족 [추론] · 링크는 한 번·7일·가족당 대기 1건 · BR-ACC-01 예외는 이웃 관계에만 · 이웃에게는 지금 접속 중인지(참/거짓)만 보인다. 마지막 접속 시각은 보이지 않는다(2026-11-04 이제민 지시, 마스터플랜 3-3 #167) |

## 기본흐름

1. 보호자 A가 가족 보호자 화면에서 [이웃 초대 링크 복사하기] → 링크를 카카오톡으로 보낸다(`POST /v1/neighbors/invites`).
2. 보호자 B가 링크(`/app/neighbor?token=…`)를 연다. 로그인 전이면 로그인(카카오) 뒤 이어진다.
3. B가 [이웃 되기]를 누르면 두 가족이 이웃이 된다(`POST /v1/neighbors/accept`). 링크는 쓰인 것으로 기록된다.
4. B가 미술관 밖(마을, `/app/town`)으로 나가면 A 가족 건물의 문이 열려 있다. 들어가면 로비에 A의 아이마다 미술관 문이 있다.
   - 3D 화면(`/app/world`, 마스터플랜 3-3 #167): 3 직후 B의 [친구] 창 맨 위에 A가 뜬다. A의 화면은 10초 안에 새 친구 카드를 띄운다. 양쪽 모두 [들어가기] 한 번으로 5로 간다.
5. B가 A 아이의 미술관에 들어가 둘러본다(`GET /v1/visit/children/{id}/gallery`, 파일은 `/v1/visit/files/*`).

## 대체흐름

- A1 이미 이웃: 3에서 그대로 204, "이미 이웃이에요".
- A2 이웃 끊기: 어느 쪽이든 [이웃 끊기](`DELETE /v1/neighbors/{buildingId}`) → 서로의 문이 즉시 잠기고 방문 중이던 화면은 다음 요청에서 404 → 마을로.
- A3 초대 취소: A가 대기 중 링크를 취소(`DELETE /v1/neighbors/invites/{id}`).

## 예외흐름

- E1 링크가 쓰였거나 7일이 지났거나 취소됨: 400 token_invalid — "이 이웃 링크는 이미 쓰였거나 끝났어요. 새 링크를 받아 주세요".
- E2 자기 가족의 링크: 409 own_family.
- E3 이웃 30가족: 409 neighbor_full.
- E4 이웃이 아닌 가족의 아이 미술관 주소를 직접 열면 404(존재를 숨김).
