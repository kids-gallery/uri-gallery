## 1. 핵심 개념

공개 사전학습 모델을 **새로 학습하지 않고 이어 붙여** API 서버 뒤에서 서빙한다. 한 장의 사진이 여러 모델을 거치며 중간 결과를 재사용하고, 어느 모델이 실패해도 **한 단계 낮춘 결과**가 돌아온다.

흐름: 접수 → 배경 분리 → 판정 제안(제로샷 분류 + 관절 기하 규칙) → **보호자 확정** → 움직임 / 2.5D 입체 부조 / 원본 액자 생성(낮춤 체인) → 보호자 결과 확인·승인 → 이야기 입력(P0.5: 키워드 설명 초안) → 전시.

범위

| 구간 | 포함 |
|:--:|---|
| P0 | 판정 제안 · 움직임 · 2.5D · 액자 · 전시 · 삭제 · 모델별 지표 · 모델 평가·승격 · API활용 메뉴 · 외부 모델 기능 네 가지(UC12, D17) |

## 3. 서빙 구조

- API 서버가 접수·상태·권한을 맡는다. 모델을 직접 import하지 않는다. 작업 계약 하나 뒤에 서빙 3종을 둔다. 모델마다 어댑터와 버전 매니페스트를 둔다.
- 서빙 3종: **CPU 비전 워커**(M1·M2·M3·M4, 비동기 작업 큐) · **GPU 워커**(M5·M7, 전용 큐, 모델 상주. GPU가 없으면 M5는 CPU에서 실행하고 M7은 비노출) · **LLM 서버**(M6, 짧은 동기 요청 또는 스트리밍).
- 기반: DB 작업 테이블 + 전용 워커, S3 호환 저장소, Prometheus·구조화 로그. TorchServe·Ollama 포트는 내부망에만 둔다.
- 추가 요구 R3(2026-09-28): 모델 기능은 Python 가상환경 + uvicorn으로 띄운 API로 제공한다. 추가 요구 R4: API 서버는 엔드포인트·가이드라인·매뉴얼을 담은 'API활용' 메뉴를 갖춘다.
- 스택 미확정: Intent-Plan에 웹스택 후보 4종(Vue+Node+MariaDB, React+FastAPI+PostgreSQL, Django, Next.js)이 있고, Intent-Specify는 FastAPI+PostgreSQL안과 Vue+Node+MariaDB안을 언급한다. [추론] 모델 서빙 계층(워커·어댑터·모델 기능 엔드포인트)은 R3와 모델 생태계 때문에 Python(uvicorn)으로 고정하고, 보호자 앱 API의 스택만 `/speckit.plan`에서 정한다. 이 판단은 미해결 사항에 올린다.

## 5. 상태 모델

작품 상태: `접수됨` → `판정 중` → `확정 대기` → `처리 중` → `확인 대기` → `승인됨` → `전시 중`(필수 이야기 입력 뒤) · 종료 상태 `처리하지 못함`(인프라 재시도 소진 = 결과 미도달) · `삭제 중`.

결과 종류: `움직임(animated)` · `2.5D 부조(relief)` · `원본 액자(frame)` · P1 `3D 조각(sculpture)`.

단계 작업(작품당 여러 개): `분리(M1)` · `판정(M2+M3 관절+M4)` · `움직임 렌더(M3)` · `깊이·부조(M5)` · `설명(M6)` · `3D(M7)`. 각 단계 작업은 모델 ID·버전·상태·시도 횟수·처리 시간·낮춤 원인 또는 오류 분류를 가진다.

낮춤 체인 (품질 미달 → 재시도 없이 한 단계 낮춤):
- 움직임 → 2.5D 부조 → 원본 액자
- 3D 조각(P1) → 2.5D 부조 → 원본 액자
- 설명: LLM 초안 → 템플릿 설명 → 보호자 직접 입력

인프라 장애(엔진 다운·시간 초과·저장소·DB·모델 미준비)는 **낮춤이 아니다.** 같은 단계를 최대 3회 재시도하고, 소진되면 `처리하지 못함`으로 알리고 "결과 미도달"로 집계한다(목표 0). 이때 보호자는 모델이 필요 없는 원본 액자로 걸기를 고를 수 있다.

결과 원인 분류(서로 섞지 않는다): ① 보호자 선택(확정 시 액자·2.5D를 고름) ② 모델 낮춤(품질 미달로 한 단계 낮춤, 어느 단계에서 어디로) ③ 보호자 전환(결과 확인 시 낮춘 결과·액자로 바꿈) ④ 인프라 실패(재시도 중/소진) ⑤ 결과 미도달.

마스크 출처: 2.5D 마스크는 M1 분리 결과가 기본이다. M1이 실패하면(품질 미달) 2.5D를 건너뛰고 원본 사진 전체를 액자로 건다. 사람을 찾지 못한 그림도 M1 마스크로 2.5D를 만들 수 있다.

판정 제안: 문구만 보여 준다("움직일 수 있을 것 같아요" / "입체 부조가 어울려요" / "액자로 거는 것을 추천해요" [추론 문구]). 점수는 노출하지 않는다. 엔진 사람 점수 단독으로 제안하지 않는다. 제안값·확정값·수정 여부를 기록한다(판정 수정률). 제안이 늦거나 실패해도 보호자는 직접 확정할 수 있다 [추론].

## 7. spec FR v2.0 번호 (spec 개정과 모든 UC가 같은 번호를 쓴다)

기존 FR-1~FR-19는 번호를 유지하고 내용을 고친다. 바뀌는 것:
- FR-3: "보호자 답으로 경로 결정" → "판정 제안(M1·M2·M3·M4)을 보여 주고 보호자 확정값으로 경로 결정"
- FR-5: 결과 분류 → 결과 종류 4종(움직임/2.5D/액자/P1 3D) + 낮춤·인프라 실패 분리
- FR-13: 지표 → Intent [미션] 서빙 지표 전체
- FR-16·17: 엔진 재현·평가 → 모델 7종 재현·평가 묶음
