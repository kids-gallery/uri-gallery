# 보관·삭제·복원 정책 초안 (#105·#107·#113)

2026-11-04 사용자 답변으로 **운영 책임자 신지현**을 최종 결정 책임자로 기록한다. 로그 7일·백업 7일, RPO 24시간·RTO 1시간은 아직 초안이다. 확정 정책·운영 달성 결과로 표시하지 않는다.

| 대상 | 제안 보관·삭제 | 실행·승인 책임 |
|---|---|---|
| 온라인 원본·결과 | 가족이 보관하는 동안 유지. 삭제 접수 후 조회에서 제외하고 작업 중단·파일 삭제·DB 정리를 수행 | 가족의 삭제 요청 / 운영 담당 확인 |
| 임시 파일 | 단계 완료·실패 뒤 기존 sweeper 기준으로 정리. 장기 보관하지 않음 | 기존 sweeper, 운영 담당 |
| DB·파일 백업 | 매일 1회 일관된 snapshot, 7일 후 만료 제안. 운영 키는 별도 접근 통제·암호화 보관 | 신지현. 별도 클라우드 저장소 공급자·접근 설정 미정 |
| 정제 업무 로그 | Loki 7일 제안. 사진·이야기·이메일·토큰·원시 예외는 수집 금지 | 운영 담당, 검토자 |
| Docker 원시 로그 | 파일당 10MB×3 회전. 이것은 7일의 시간 보관 보장이 아님. 원시 로그의 값 검사와 시간 만료 설계는 별도 필요 | 운영 담당 |
| 삭제 재적용 이력 | 백업의 마지막 유효 기간이 끝날 때까지 작품 내부 번호·요청 시각·근거만 별도 보관 제안. 가족 사진·별칭·이메일 없음 | 삭제 요청 확인자·복원 담당. 실제 권한·위치 미정 |

RPO 24시간은 실제 매일 성공한 백업과 실패 통지가 있어야 달성된다. RTO 1시간은 용량과 복원 범위별 실측으로 판단한다. 이번 작은 합성 DB 결과가 운영 목표 달성을 입증하지 않는다.

## 복원 격리 해제 순서

1. 새 프로젝트·볼륨으로 복원한다. 메일 발송을 끄고 외부 포트 없이 시작한다.
2. snapshot manifest와 파일 SHA-256을 검사하고, DB와 파일을 같은 쓰기 중지 구간에서 백업했는지 확인한다.
3. 모든 보호자 세션과 미사용 메일 토큰을 무효화한다. 작업 lease는 만료시켜 재획득하게 한다.
4. snapshot 이후의 **독립 삭제 이력**을 확인해 삭제 상태와 작업 취소를 재적용하고 sweeper로 마친다. 이력이 없으면 외부 공개하지 않는다.
5. 재로그인·아이·작품·원본 체크섬·작업 상태·삭제 작품 404를 확인한다. 쓰기 재개와 공개는 담당자가 검토한다.

시험용 이력 파일의 manifest 해시는 잘못된 snapshot 혼합을 막지만 서명·위변조 방지나 운영 감사 권한 구현은 아니다. 실제 이력 저장소·권한을 정하고 신지현이 정책을 승인하기 전 #113 완료로 보지 않는다.

## 서비스 종료

종료 공지 → 신규 접수 중단 → 보호자가 작품을 내려받을 기간 제공 → 온라인 데이터 삭제 → 마지막 백업 만료 → 잔여 파일 점검 순서를 제안한다. 공지 기간·반출 범위·책임자·최종 삭제 날짜는 팀이 정한다. 일괄 내보내기는 미구현이며 별도 작업이다.
