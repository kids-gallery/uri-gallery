## 1. 이 문서는 무엇인가

우리 아이 미술관 화면을 만들 때 **색, 글꼴, 간격, 버튼 모양**을 어떻게 정하는지 알려 주는 사용 설명서다.

- 뼈대는 Figma 사이트의 디자인 언어다. 흑백의 깨끗한 틀 위에 파스텔 색 면을 한 장씩 붙이는 방식이다.
- 이 언어를 고른 이유는 서비스의 약속과 잘 맞기 때문이다.
  - 인터페이스는 흑백으로 물러서고, 색은 아이의 작품에서 나온다.
  - 색 면은 장식이 아니라 "여기부터 다른 이야기"라는 구간 표시로 쓴다.
- 토큰 값(색 코드, 크기, 굵기)은 DESIGN.md를 **바꾸지 않고** 그대로 쓴다.
- 우리 서비스에 맞춰 정한 부분은 모두 `[제안]`으로 표시했다. §9에 모아 두었다.

| 파일 | 역할 |
|---|---|
| `DESIGN.md` | 원천. getdesign이 설치한 Figma 디자인 분석. 토큰의 기준값 |
| `스타일가이드_우리아이미술관.html` | 눈으로 보는 스타일가이드. 토큰 견본, 타이포 표본, 컴포넌트, 적용 예시 |
| `스타일가이드_메뉴얼_우리아이미술관.md` | 이 문서. 언제 무엇을 쓰는지, 어떤 규칙을 지키는지 |

## 2. 빠르게 쓰기

### 2.1 스타일가이드 열기

```bash
open design/style-guide/스타일가이드_우리아이미술관.html      # macOS
```

인터넷에 연결되어 있으면 웹 글꼴(Inter · Pretendard · JetBrains Mono)이 적용된다. 연결이 없으면 시스템 글꼴로 대신 보인다.

### 2.2 토큰을 코드에 가져오기

HTML 파일 맨 위 `<style>`의 `:root { … }` 블록이 토큰 전체다. 이 블록을 프로젝트 공통 CSS로 복사해 쓴다. 이름 규칙은 다음과 같다.

| DESIGN.md 표기 | CSS 변수 |
|---|---|
| `{colors.block-lime}` | `--color-block-lime` |
| `{rounded.pill}` | `--r-pill` |
| `{spacing.section}` | `--s-section` |
| `{typography.body}` | 클래스 `.t-body` |

```css
.my-button {
  background: var(--color-primary);
  color: var(--color-on-primary);
  border-radius: var(--r-pill);
  padding: 10px 20px;
}
```

### 2.3 글꼴

DESIGN.md의 `figmaSans`와 `figmaMono`는 공개 서체가 아니다. 그래서 DESIGN.md가 권하는 대체 서체를 쓰고, 한글 서체를 더했다.

| 역할 | 원문 | 이 프로젝트 | 불러오는 곳 |
|---|---|---|---|
| 본문 · 제목 (영문·숫자) | figmaSans | **Inter** (가변 300~700) | Google Fonts |
| 본문 · 제목 (한글) | — | **Pretendard Variable** `[제안]` | jsDelivr |
| 라벨 · 캡션 | figmaMono | **JetBrains Mono** 400 | Google Fonts |

```css
--font-sans: "Inter", "Pretendard Variable", Pretendard, system-ui, sans-serif;
--font-mono: "JetBrains Mono", "SF Mono", Menlo, monospace;
```

Inter에는 한글이 없다. 그래서 한글 글자는 자동으로 Pretendard로 그려진다. Pretendard도 가변 굵기라서 320·330·340 같은 세밀한 굵기가 그대로 먹힌다.

## 5. 컴포넌트

HTML 스타일가이드 §05에 모두 실물로 있다. 클래스 이름은 HTML과 같다.

### 5.1 버튼

> v2(D26 ⑥): 보조 버튼(`btn-secondary`)은 바탕이 아이보리라 면으로 구분되지 않으므로 **빨간 1px 안쪽 테두리**를 둔다.

| 컴포넌트 | 클래스 | 언제 |
|---|---|---|
| `button-primary` | `.btn.btn-primary` | 화면의 **주 행동 하나**(작품 올리기, 이대로 만들기) |
| `button-secondary` | `.btn.btn-secondary` | 주 버튼의 짝(나중에 할게요, 다시 찍기). 테두리 없음 |
| `button-tertiary-text` | `.btn.btn-tertiary` | 가벼운 이동(전시 규칙 보기) |
| `button-icon-circular` | `.btn.btn-icon` | 이전·다음, 닫기. 40px, 터치 기기 44px |
| `button-icon-circular-inverse` | `.btn.btn-icon.btn-icon-inverse` | 어두운 면 위 재생·정지 |
| `button-magenta-promo` | `.btn.btn-magenta` | 프로모 배너 안에서만, 페이지당 한 번 |

```html
<button class="btn btn-primary" type="button">작품 올리기</button>
<button class="btn btn-secondary" type="button">나중에 할게요</button>
<button class="btn btn-icon" type="button" aria-label="다음 작품">&rarr;</button>
```

- 한 화면에 검정 주 버튼이 둘 보이면 하나를 흰 버튼으로 바꾼다.
- 누른 상태는 색을 바꾸지 않고 살짝 작아지게(scale .97) 한다.
- 아이콘 버튼에는 반드시 `aria-label`을 단다.
- 버튼 최소 높이는 44px(터치 기준)이다.

### 5.2 탭 (pill toggle)

```html
<div class="tabs" role="tablist" aria-label="결과 종류">
  <button class="tab" role="tab" aria-selected="true">전체</button>
  <button class="tab" role="tab" aria-selected="false">움직이는 그림</button>
</div>
```

- 선택된 탭은 주 버튼과 같은 **검정 면**이다. 색 있는 탭으로 바꾸지 않는다.
- 쓰는 곳: 결과 종류 거르기, 아이 고르기(가족 전시).

### 5.3 입력칸

```html
<div class="field">
  <label for="title">작품 제목</label>
  <input id="title" class="input" placeholder="예: 바다에 간 날">
</div>
```

- 이름표는 `body-lg`(20px), 입력 글자는 `body`(18px)다. 높이는 최소 48px이다.
- **초점**: 채움 색을 바꾸지 않고 2px 검정 링으로 표시한다.
- **오류** `[제안]`: DESIGN.md에 없다. "검정 링 + 입력칸 아래 안내 문장 + `aria-invalid="true"`" 조합을 쓴다. 빨간색을 들이지 않고, 색만으로 오류를 알리지도 않는다.
  - 예: 제작 당시 연령 "21" → "만 나이 0~18 사이로 적어 주세요." (BR-STY-02)

### 5.4 카드 · 타일

| 컴포넌트 | 클래스 | 모양 | 쓰는 곳 |
|---|---|---|---|
| `pricing-card` | `.card` | 흰 바탕, 1px 선, 24px 모서리 | 안내 카드, AI 설명 카드 |

| `comparison-checkmark` | `.check` | 초록 체크 16px | 지원 여부 표시 |

### 5.5 컬러 블록 섹션 (대표 컴포넌트)

```html
<section class="cb cb-lime full-bleed-m">
  <p class="t-eyebrow">01 · 원칙</p>
  <h2 class="t-display-lg">작품이 먼저 보이게</h2>
</section>
```

- 클래스는 `.cb` + `.cb-lime | cb-lilac | cb-cream | cb-mint | cb-pink | cb-coral | cb-navy`다.
- 모양: 24px 모서리, 48px 안쪽 여백, 그림자 없음
- `.full-bleed-m`을 붙이면 768px 이하에서 화면 끝까지 닿고 모서리가 없어진다.
- **새 구간을 만들 때는 어떤 블록에 둘지를 가장 먼저 정한다.**
- 블록 안 제목은 `headline` 또는 `subhead`, 블록 밖 본문은 `body`다.

## 6. 우리 아이 미술관 적용 규칙

이 절은 모두 `[제안]`이다. 디자인 언어를 서비스 명세(spec v2.1)와 업무규칙에 맞춰 옮긴 것이다. 근거 규칙은 `design/REF_재작성공통기준_우리아이미술관.md`에 있다.

### 6.1 판정 제안과 보호자 확정 (UC2)

- 제안은 **문구**로만 보여 준다. 예: "이 작품은 움직이는 그림으로 만들어 볼까요? 다른 방식도 고를 수 있어요."
- 점수·확률·신뢰도 막대를 보이지 않는다 (BR-SUG-02).
- 선택지 세 개(움직이는 그림 / 2.5D 부조 / 원본 액자)를 같은 모양의 알약으로 나란히 둔다.
  - 제안된 것에만 모노체 "제안" 라벨을 붙인다.
  - 다른 선택을 막거나 흐리게 하지 않는다 (BR-SUG-03).
- 선택된 알약은 검정 면(탭과 같은 규칙)이다.

### 6.2 처리 상태 (UC3 · UC4)

| 상태 | 표시 `[제안]` |
|---|---|
| 접수됨 | 옅은 테두리 알약 + 속이 빈 점 |
| 처리 중 | 검정 테두리 알약 + 채운 점 |
| 다시 시도하는 중 | 같은 모양, 문구만 다름 |
| 확인 대기 | 같은 모양, 문구만 다름 |
| 처리하지 못했어요 | 같은 모양, 문구만 다름 |

- 상태는 **모노체 문구와 점 모양**으로 구분한다. 빨강·노랑 같은 새 강조색을 들이지 않는다.
- 낮춤 안내("움직임 대신 2.5D로 만들었어요")는 진행·결과 확인 화면(UC3·UC4)에서만 보인다. 전시 화면에는 낮춤 원인과 결과 원인을 표시하지 않는다 (D3, BR-EXH-07).
- 실패를 성공처럼 꾸미는 문구를 쓰지 않는다 (BR-FBK-03). 화면 문구는 C2 작업(`docs/기록/C/C_화면문구.md`, U10)에서 확정한다.

### 6.3 가족 전시 (UC6)

- 아이 고르기는 탭, 연령 묶음은 `eyebrow`("만 5세"), 작품은 제작일 순서로 3열 → 2열 → 1열로 놓는다.
- 작품 카드는 회색 타일 안에 흰 이미지 틀(8px 모서리)을 둔다. 아래에 날짜·종류(캡션), 제목(20px 700), 아이의 한마디가 온다.
- **원본 액자와 2.5D도 움직이는 그림과 같은 카드, 같은 크기**로 건다. "실패"·"대체" 표시를 붙이지 않는다 (BR-EXH-04).
- 재생·시차 효과는 보호자가 고를 때만 한다. 자동 재생, 무한 피드를 두지 않는다 (BR-EXH-03).
- 점수, 발달 평가, 아이 간 비교를 보여 주지 않는다.

### 6.4 작품 상세 (UC6 · UC10)

- 작품 상세는 크림 블록(`cb-cream`) 하나에 둔다.
- 순서: 작품 → 날짜·연령·종류(캡션) → 제목(headline) → **아이의 한마디(body-lg, 따옴표)**
- 아이의 한마디 아래에 "아이의 한마디 · 입력한 글자 그대로" 캡션을 둔다.
- AI 설명(P0.5)은 흰 카드(`.card`) 안에 따로 두고 모노체 **"AI 작성"** 표시를 붙인다. 아이의 한마디와 같은 상자에 섞지 않는다 (D6).

### 6.6 전시 공간 고전 시안 A · B (D30, 시안 — 팀 선택 전, 2026-09-30)

> **2026-09-30 선택(D31 ①)**: 액자는 **금빛**(원칙 01 흑백 프레임의 전시 공간 예외로 확정), 벽은 **크림 한 가지 + 보호자가 고르는 벽 색**(원칙 02 지킴 — 한 화면에 벽색 하나). 이어서 홈은 걸어 다니는 미술관(SD_02 §17-6)이 되고, 아래 목록형은 [한눈에 보기]로 옮긴다.

홈 `/app`을 "이탈리아 고전 대형 미술관" 분위기로 바꾸는 시안이다. 정본은 SD_02 §17-5다(요소표 · 토큰 · 자원 출처). 여기에는 이 문서의 원칙과 어떻게 맞물리는지만 적는다.

| 원칙(§3) | A. 건축만 고전 | B. 전체 고전 |

| 01 흑백 프레임 | 지킨다 — 액자는 검은 테 + 흰 매트 | **예외** — 전시 공간의 액자만 금빛 |
| 02 컬러 블록은 한 화면에 하나 | 지킨다 — 벽은 크림 한 가지 | **예외** — 방마다 깊은 벽색(진홍 · 짙은 녹색 · 남색) |

- 관리 화면(작품 관리 · 아이 · 가족 · 운영)은 이 시안과 무관하게 지금 스타일가이드 그대로다.

### 6.5 운영·팀 화면 (UC8 · UC9 · UC11)

- 같은 토큰을 쓰되, 구간 구분에는 코랄 블록(`cb-coral`)을 쓴다 `[제안]`.
- 'API 활용' 메뉴의 엔드포인트 표는 `table.plain`, 코드 예시는 `code` 스타일을 쓴다.

## 8. 해야 할 것 · 하지 말 것

**해야 할 것**

- 검정 주 버튼은 화면당 하나만 둔다.
- 새 구간은 먼저 어떤 컬러 블록에 둘지 정한다.
- 컬러 블록 사이에는 흰 여백(96px)을 둔다.
- 굵기는 320 · 330 · 340 · 480 · 540 · 700 중에서만 고른다.
- 모노체는 대문자와 양의 자간으로 라벨에만 쓴다.
- 모든 글자 버튼은 알약, 아이콘 버튼은 원으로 만든다.
- 상태와 오류는 색과 함께 문구나 모양으로도 알린다.

**하지 말 것**

- 회색 본문 글자를 쓰지 않는다. 위계는 굵기로 만든다.
- 컬러 블록에 그림자를 넣지 않는다.
- 팔레트 밖 색(주황, 빨간 경고색 등)을 들이지 않는다.
- 한 화면에 컬러 블록 둘을 동시에 보이지 않는다.
- 네모 버튼을 만들지 않는다.
- 선택된 탭을 색 있는 면으로 바꾸지 않는다.
- 마젠타를 한 페이지에 두 번 쓰지 않는다.
- 점수, 발달 평가, 아이 간 비교를 화면에 두지 않는다(서비스 규칙).
