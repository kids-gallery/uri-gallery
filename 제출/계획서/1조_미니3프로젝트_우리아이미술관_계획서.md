## 1. 프로젝트 주제

아이는 매일같이 그림을 그리고 무언가를 만들지만, 가정에서는 그 작품을 오래 간직하고 다시 꺼내 보기 어렵다. 종이와 만들기 작품은 금방 쌓여 버려지거나 상자에 들어가고, 작품을 만들 때 아이가 한 말과 나이, 날짜 같은 맥락은 따로 기록되지 않아 시간이 지나면 "무엇을 왜 그렸는지"가 사라진다. 사진을 찍어 두더라도 배경과 손이 섞이고 어떤 방식으로 보여 줄지 매번 고민해야 해서, 가족이 함께 다시 볼 계기가 잘 생기지 않는다.

본 프로젝트는 휴대폰으로 찍은 아이 작품 사진 한 장에서 작품을 찾아내 미술관의 작품으로 바꿔 거는 **가족용 미술관 서비스**를 만든다. 모델을 새로 학습하지 않고 **공개 사전학습 모델을 이어 붙여** API 서버 뒤에서 서빙한다. 사진에서 작품을 분리하고(배경 분리), 무엇을 그렸는지 판정을 제안하고(제로샷 분류 + 관절 기하 규칙), 사람·캐릭터 그림은 원본 선을 살린 **움직이는 그림**으로, 움직이기 어려우면 **2.5D 입체 부조**로, 그것도 어려우면 **원본 액자**로 만든다. 어느 모델이 실패해도 **한 단계 낮춘 결과**가 돌아오도록 설계하고, 결과는 아이 한 명마다 한 채씩 지어지는 걸어 다니는 3D 미술관에 전시한다.

## 2. 프로젝트 목적

본 프로젝트의 목적은 공개 사전학습 모델만으로 "사진 한 장 → 작품 분리 → 전시 방식 제안 → 움직임·입체·액자 결과 → 가족 전시"로 이어지는 흐름을 실제 서비스 수준으로 서빙할 수 있는지 검증하고, 모델이 실패하거나 느려져도 보호자가 결과를 받지 못하는 일이 없도록 **낮춤 체인과 원인 분리**를 갖춘 서빙 구조를 만드는 것이다.

먼저 팀원이 직접 그린 그림으로 평가 묶음을 만들고, 모델마다 같은 조건에서 품질과 처리 시간을 측정한다. 모델 채택과 승격은 정확도뿐 아니라 처리 시간, 실패 시 낮춤 동작, 원본 보존, 아동 정보 보호를 함께 고려하여 결정한다. 모델 점수와 확률은 보호자 화면에 드러내지 않고, 모델은 제안만 하며 최종 결정은 보호자가 한다.

개발은 아래의 세 단계로 진행한다. 각 단계에서 얻은 측정 결과와 문제를 다음 단계의 과제로 연결한다.

```text
[페이즈 1] 모델 재현과 서빙 구조
모델 7종 재현 → 어댑터·버전 매니페스트 → 서빙 3종 분리(CPU 비전·GPU·LLM) → 낮춤 체인·원인 기록
        │
        └── 평가 묶음 1차 측정으로 모델별 품질 임계값·시간 상한 결정
                         ↓
[페이즈 2] 보호자 흐름과 외부 모델 API
접수 → 판정 제안 → 보호자 확정 → 결과 확인 → 이야기 → 가족 전시 · 외부 모델 기능 엔드포인트 4종 · API 점검
        │
        └── 실제 사용 관찰로 막히는 화면·말투·조작 확인
                         ↓
[페이즈 3] 경험 다듬기와 공개
아이마다 3D 미술관 · 캐릭터 만들기 · 미술관 마을(이웃 방문) · 견본 미술관 · 배포 확인·진짜 응답 감시
                         ↓
                  p1.sumzip.com 공개
```

최종적으로 다음 네 가지를 제공하는 것을 목표로 한다.

1. 사진 한 장으로 작품만 분리하고 전시 방식(움직임·2.5D·액자)을 제안하는 기능
2. 모델이 실패해도 한 단계 낮춘 결과가 돌아오고, 인프라 장애와 모델 품질 낮춤을 구분해 기록하는 서빙 구조
3. 아이의 말·나이와 함께 작품을 간직하고, 가족이 함께 걸어 다니며 보는 아이 미술관
4. 외부 개발자가 API 키로 호출할 수 있는 모델 기능 엔드포인트와 'API활용' 문서

## 6. 서비스 구현 방향

서비스는 보호자가 아이 작품 사진을 올리면 작품만 분리하고, 무엇을 그렸는지 판정을 제안해 보호자가 전시 방식을 확정하도록 한다. 확정된 방식에 따라 백그라운드 작업으로 움직이는 그림·2.5D 입체 부조·원본 액자를 만들고, 보호자가 결과를 확인하면 아이 미술관에 건다. 미술관 규칙처럼 한 번 걸린 작품은 바꾸지 않고, 제목·아이의 한마디·보호자 감상은 올릴 때 함께 남기며, 설명은 큐레이터 해설(규칙 해설과 AI 작성 해설)이 맡는다.

아이 한 명마다 미술관 한 채가 지어지고, 보호자와 아이는 캐릭터를 만들어 걸어 다니는 3D 미술관(가운데 홀 양옆의 나이별 전시실, 벽 액자, 만들기 작품 받침대)에서 작품을 본다. 가족은 미술관 마을의 건물 한 채가 되며, 초대 링크로 이웃이 된 가족끼리만 서로의 미술관을 방문할 수 있다(방문자에게는 그림·별칭·제목만 보인다). 처음 온 보호자는 로그인 없이 견본 미술관을 걸어 볼 수 있다.

예측·처리 로직은 모델마다 하나의 어댑터에서만 수행하고, 보호자 앱과 외부 모델 API는 같은 어댑터와 매니페스트를 호출한다. 모델 기능은 외부 개발자용 엔드포인트(`segment`·`classify`·`relief`, 팀 내부 `pose`)로도 제공하고, 'API활용' 메뉴의 문서는 실제 계약에서 만들어 어긋나지 않게 한다.

| 항목             | 작성 내용                                                                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 서비스 대상      | 아이 작품을 간직하고 가족과 함께 보고 싶은 보호자(주 사용자), 보호자와 함께 화면을 보는 아이(주 수혜자), 모델 기능을 연동하려는 외부 개발자, 서비스 상태를 보는 운영 팀원            |
| 서비스 흐름      | 사진 올리기(자동 펴기·모서리·회전, 제목·한마디·감상 선택 입력) → 작품 분리(M1) → 판정 제안(M2·M3·M4) → 보호자 확정 → 움직임(M3)/2.5D(M5)/원본 액자(낮춤 체인) → 결과 확인 → 아이 미술관 전시 |
| 예상 주요 기능   | 카카오 로그인, 캐릭터 만들기(이름·동물 친구·미술관 모양), 걷는 3D 아이 미술관(방 버튼·미니맵·작품 거는 장면), 해설 읽어 주기·배경 음악, 가족 댓글, 미술관 마을·이웃 초대, 견본 미술관, 외부 모델 API·API활용 메뉴, 운영자 모델 상태·지표 화면 |
| 구현 구조        | 브라우저(Vue 3 · CSS 3D, 3D 엔진 없음) → nginx(HTTPS) → 보호자 앱 API(Node.js · Express) → MariaDB 작업 큐 → 워커(CPU 비전 · GPU) · LLM 서버 · 모델 API(FastAPI) → 모델 어댑터·매니페스트 · 파일 저장소 |
| 배포·운영        | Docker 없이 pm2(app-api · model-api · worker-cpu · worker-gpu · sweeper) · 생존·준비(모델별)·Prometheus 지표 · 배포 확인과 자동 되돌림 · 응답 내용 감시                                     |
| 검증 방향        | API 단위·계약 시험(Vitest · Supertest · 응답 계약 검증), 모델 서버 시험(pytest), 화면 시험(Playwright 390·1440px, 접근성), 장애 주입 시험, 평가 묶음 측정, 사용 관찰                          |

### 예상 결과 및 활용 방향

- 사진 한 장과 확정 한 번으로, 원본의 선과 색을 알아볼 수 있는 움직이는 그림·입체 부조·액자를 받을 수 있을 것으로 예상한다.
- 모델이 실패하거나 느려져도 낮춘 결과가 돌아오고, 인프라 장애와 모델 품질 낮춤이 분리 기록되어 어떤 모델을 먼저 고쳐야 하는지 운영 지표로 판단할 수 있을 것으로 예상한다.
- 들고 찍은 사진·책상 배경·누운 사진 등 실제 촬영 조건에서의 약점을 평가 묶음으로 확인하고, 올리기 전 편집과 분리 후처리로 보완한다.
- 차별점은 개별 기능(보관·그림 움직이기·가상 갤러리)이 아니라 "분리 → 판정 제안 → 움직임·입체·액자 → 전시"로 이어지는 조합과 걷는 미술관 경험이라는 가설이며, 부모 몇 명에게 먼저 보여 주고 관찰하여 검증한다.
- 서비스는 아이의 기억을 꾸며내는 도구가 아니라 다시 꺼내 보는 수단으로 활용하며, 모델 결과의 한계(판정은 제안일 뿐임, 2.5D는 평면 그림에 깊이를 더한 효과일 뿐 3D 복원이 아님)를 화면과 문서에 명확하게 알린다.
