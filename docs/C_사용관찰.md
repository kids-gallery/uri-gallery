## 1. 방법

- 계정: 시험 계정 `abc123@naver.com`(가족 공간 1개, 아이 "시험아이" 1명, 작품 2개 — 전시 중 1 · 확인 대기 1). 새 계정은 만들지 않았다.
- 도구: Playwright(chromium, 헤드리스). 화면 폭 **390×844**(휴대폰)와 **1440×900**(데스크톱) 두 가지.
- 걸어 본 화면: 첫 방문 `/app/welcome`(빈 브라우저) → 입장하기 → 로그인(Enter 제출) · 가입 · 로그인 정보 찾기(보기만) → 미술관 홈 `/app` → 전시실 `/app/hall` · 세관 누르기 · 작품 앞 `?art=1` · Esc → 작품 올리기 `/app/upload`(파일 고르지 않음) → 작품 관리 `/app/works` → 작품 상세 `/app/artworks/1` · `/6` · 결과 확인 `/6/review` · 이야기 `/1/story` · `/6/confirm`(→ review로 넘어감) · 없는 작품 `/999` → 우리 아이 `/app/children`(삭제 대화상자 열고 취소, 별칭 고치기 열고 취소) → 가족 `/app/family` → 계정 `/app/account` → 로그아웃.
- 측정: 화면별 가로 스크롤(scrollWidth > 화면 폭), 44px 미만 누름 대상, 좁은 칸에서 글자가 세로로 갈라지는 곳, 페이지 로드 시간(networkidle까지).
- **하지 않은 것**: 작품 올리기 · 판정 확정 · 결과 승인("좋아요"/"액자로 걸기"/"다시 찍기") · 이야기 저장 · 삭제 · 초대 · 비밀번호 변경 · 아이 추가/수정. 모델이 공유 GPU 서버에서 돌기 때문에 처리를 일으키지 않으려고, 또 시험 계정 데이터를 바꾸지 않으려고 쓰기 동작을 모두 뺐다. 스크립트에서 로그인·로그아웃 외의 POST/PUT/PATCH/DELETE 요청을 막아 두었고, 막힌 요청은 0건이었다(쓰기 시도 없음).
- 그래서 **올리기 → 판정 → 확정 → 처리 대기 → 결과 → 이야기 → 전시** 흐름의 진행 중 화면(판정 중, 확정 선택, 처리 중·다시 시도, 막힘 안내)은 이번에 보지 못했다. 4절에서 사람이 본다.
- 스크린샷: 에이전트 세션 임시 폴더(`scratchpad/t139/`, `m_*`=390, `d_*`=1440). 저장소에는 넣지 않았다.

## 3. 잘 된 점

- **속도**: 모든 화면이 1초 안에 떴다(로그인 뒤 0.65~0.9초). 흰 화면으로 기다리는 곳이 없다.
- **페이지 가로 스크롤 없음**: 390에서도 본문은 한 화면 폭 안에 들어온다(메뉴 줄만 예외).
- **개인정보 안내가 분명하다**: "실명 대신 가족이 부르는 별칭을 적어 주세요", "이름 - 전화번호 - 아이 정보는 받지 않아요", "이메일이 로그인 아이디예요 - 따로 아이디를 만들지 않아요". 무엇을 받지 않는지 먼저 말해 준다.
- **삭제 대화상자**가 지워지는 범위("작품 2개가 모두 지워져요")와 남는 것("통계용 숫자만")을 구체적으로 말한다. 취소가 바로 옆에 있다.
- **올린 뒤 안내**: "기다리지 않고 화면을 닫아도 계속돼요" — 처리 대기 불안을 줄인다.
- **작품 관리 표의 할 일 버튼**("결과 확인으로", "전시 보기")이 다음 행동을 곧장 연결한다.
- **잘못된 단계 주소를 알맞은 화면으로 넘김**(`/confirm` → review, 끝난 작품 review → 상세) — 오래된 링크에서 막히지 않는다.
- **작품 앞 화면**의 전시 해설이 아이의 한마디("말이 달려요")를 그대로 인용해 가족이 보기 좋다. Esc로 전시실에 돌아온다.
- **첫 방문 흐름**: 로그인 안 된 `/app`은 welcome으로, "입장하기"는 로그인으로, 로그인 뒤 원래 주소로 돌아온다.

## 4. 팀원 관찰 때 볼 것

전제: **실제 아동의 사진·그림·이름 금지**(G20 · U13). 팀원이 직접 그린 그림이나 이미 쓰던 시험 그림만 쓴다. 관찰자는 옆에서 말없이 보고 막힌 곳·되돌아간 곳·혼잣말을 적는다(FR-18). 휴대폰 1명, 데스크톱 1명 이상.

시나리오(한 사람이 처음부터 끝까지)

- [ ] 새 브라우저로 p1 열기 → welcome에서 가입을 찾아가는가(1절 "입장하기"만 있는 문제 확인) · 걸린 시간
- [ ] 가입 → 메일 확인 → 로그인 → 아이 등록(별칭) — "별칭"을 이해하는가
- [ ] 작품 올리기: 사진 찍기/앨범 고르기, 20MB·형식 안내를 읽는가, "(비활성)" 버튼을 어떻게 받아들이는가
- [ ] 판정 중 → **확정 대기**: 제안된 판정을 그대로 받는지 바꾸는지, 바꿨다면 이유(FR-18 판정 수정 여부)
- [ ] 처리 중 · 대기 순서 화면: 기다리는 동안 화면을 떠나는지, 돌아올 길을 찾는지(작품 관리 → 결과 확인으로)
- [ ] 막힘 안내가 나오면(용량·형식·모델 없음 등): 사유 · 해제 주체 · 다음 행동을 이해하는가 — D28 문구 반영 뒤 버전으로 볼 것
- [ ] 결과 확인: 원본과 결과 차이를 알아보는가, "좋아요 / 액자로 걸기 / 다시 찍기" 중 무엇을 왜 눌렀는가, 다시 보기(원본·결과 번갈아 보기) 행동과 이유
- [ ] 이야기: "필수" 칸을 알아보는가, 전시 조건 체크 상자를 이해하는가, 저장 뒤 전시에 걸렸다는 걸 아는가
- [ ] 전시: 홈 → 전시실 → "세관"을 방으로 이해하는가 → 작품 앞 → 돌아오기
- [ ] 두 번째 보호자 초대 → 받은 쪽에서 수락 → 같은 작품이 보이는가(초대 쓰기 동작은 이 단계에서만)
- [ ] 작품 삭제·아이 삭제는 시험 작품으로만, 삭제 대화상자 문구를 읽고 멈추는가
- [ ] (P0.5) 설명 초안을 승인했는지, 얼마나 고쳤는지
- [ ] 세션마다 기록: 완료 여부 · 막힌 단계 · 막힌 이유 · 판정 수정 여부와 이유 · 다시 보기 행동과 이유 · 걸린 시간

이 문서 2절의 "헷갈림" 항목 중 실제 관찰에서도 멈춘 것은 막힘으로 올리고, 아무도 멈추지 않은 것은 사소로 내린다. 아이가 자기 작품을 알아보는지, 가족이 원본과 결과를 함께 보는지는 동의·수집 조건 확정(U13) 뒤에만 본다.
