# 팀원별 할 일과 생성형 AI 프롬프트 — 우리 아이 미술관

> 작성일: 2026-09-28 · 역할: A 최호준(모델 서빙) · B 이제민(API·오케스트레이션) · C 신지현(보호자 경험·설명) · 분담 근거: `docs/역할분담.md`

## 쓰는 법

- 프롬프트는 **순서대로 하나씩** Claude Code에 붙여 넣는다. 한 번에 여러 개를 몰아 넣지 않는다. 몰아 넣으면 뒤쪽 산출물의 밀도가 떨어진다.
- 작업은 **자기 클론**에서 한다. 셋이 pioneer1 계정과 같은 폴더를 쓰므로, 같은 폴더에서 동시에 고치면 서로 덮어쓴다.
  ```bash
  git clone /Users/pioneer1/project2610 ~/project2610-<이름>
  cd ~/project2610-<이름> && git switch -c <a|b|c>/<작업명>
  ```
- 프롬프트 안의 `@파일`은 Claude Code에서 그 파일 내용을 함께 넘기는 표기다.
- 모든 프롬프트는 [공통 규칙]을 앞에 붙인다고 보고 쓴다. 공통 규칙은 아래와 같다.

### 팀 절대 규정 — 설계서 먼저, 구현은 그다음 (2026-09-28, 신지현 결정 · 팀 전체 적용)

이 프로젝트의 설계를 바꾸거나 기능을 추가할 때는 **반드시 설계서에 먼저 반영하고 그다음에 구현한다.** 설계와 구현 내역이 늘 같아야 한다. 저장소 `CLAUDE.md`의 "절대 규정"과 같은 내용이다.

- 설계서: `design/`(REF 공통기준 · UC_00~UC_15 · UC_ALL · SD_01 · SD_02 · SD_03과 `uri_gallery_ddl.sql` · `style-guide/`), `.specify/features/우리-아이-미술관/`(spec · plan · research · data-model · contracts · tasks)
- 순서: ① 바꿀 내용이 설계서에 있는지 확인 → ② 없으면 설계서를 먼저 고친다(결정은 REF D/BR, 흐름은 UC · SD_01 게이트, 화면은 SD_02, 데이터는 SD_03 · DDL, 계약은 contracts. 도면은 렌더 확인) → ③ 설계서 커밋 → ④ 구현. 구현 커밋에는 근거 번호(UC · G · BR · S · T)를 적는다.
- 구현하다 설계서에 빈틈이나 어긋남을 찾으면 구현을 멈추고 설계서부터 고친다. 구현을 먼저 하고 설계서를 나중에 맞추지 않는다.
- 다른 사람 담당 설계서(예: B의 contracts · tasks, C의 SD_02)는 그 담당자에게 요청해 고친다.
