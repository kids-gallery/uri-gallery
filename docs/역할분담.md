## 한 줄 요약

모델은 새로 학습하지 않는다. 공개된 사전학습 모델 다섯 개를 팀 서버에 올려 이어 붙인다. 역할은 **모델을 돌리는 쪽(A)**, **모델을 묶는 서버 쪽(B)**, **보호자가 보는 화면 쪽(C)** 으로 나눈다. 셋이 만나는 곳은 **단계 작업 계약**(A↔B)과 **OpenAPI 명세**(B↔C) 두 곳뿐이다.

## 사용하는 모델 (5종)

| 모델 | 하는 일 | 서빙 | 상태 |
|---|---|---|---|
| BiRefNet | 사진에서 작품을 잘라 낸다 | CPU 비전 워커 | 라이선스·크기 확인해 선정 |
| OpenCLIP | 무엇을 그렸는지 판정을 제안한다 | CPU 비전 워커 | 라이선스·크기 확인해 선정 |
| Meta Animated Drawings | 사람 그림을 움직이게 한다 | CPU 비전 워커 | **실제로 돌려 봄** (개인 PC, 한 장 53~62초) |
| Depth Anything V2 (Small) | 움직이기 어려운 그림을 입체 부조(2.5D)로 만든다 | GPU 워커(없으면 CPU) | 라이선스·크기 확인해 선정 |
| Qwen3-4B | 작품 설명 초안을 쓴다 (P0.5) | LLM 서버 | 라이선스·크기 확인해 선정 |

- 판정 보조(관절 기하 규칙)는 모델이 아니라 규칙이다.
- 아이 사진이라 외부 API로 보내지 않는다. 모두 팀 서버 내부망에서 돌린다.

## 경계 계약 (첫날 셋이 합의)

1. **단계 작업 계약 (A ↔ B)**
   - 워커가 받는 입력, 돌려주는 결과, 응답 분류(`ok` / `quality_below` / `engine_down` / `timeout` / `storage` / `model_not_ready` / `cancelled`)를 정한다.
   - 출발점은 UC_ALL §7.3의 대응표와 SD_01 인계 계약 H1~H16이다.
   - 소유: B. 변경하려면 A의 동의가 필요하다.
2. **OpenAPI 명세 (B ↔ C)**
   - 보호자 앱용 `/v1/artworks…`·`/v1/children`·`/v1/gallery`와 설명 `/captions`를 정한다.
   - 출발점은 공통 기준 §4와 D13이다.
   - 소유: B. 화면 요구는 C가 제안한다.
3. **매니페스트 형식 (A → B·C)**
   - 모델 ID·가중치 SHA-256·런타임·이미지 다이제스트·설정 해시·활성/롤백 후보를 정한다.
   - 소유: A.

## 작업 방식

- **저장소**: 원격 저장소 하나를 두고 `main`을 보호한다. 각자 브랜치에서 작업한다(`a/model-serving`, `b/api`, `c/web`). 합칠 때는 병합 요청으로 한다.
- **공유 계정 주의**: 셋이 pioneer1 계정과 같은 폴더를 같이 쓰고 있다. 같은 파일을 동시에 고치면 서로 덮어쓴다. 각자 자기 클론(`~/project2610-<이름>`)에서 작업한다.
- **문서 정합성**: 설계 문서를 고치면 UC_ALL의 통합 결정 D1~D15와 업무규칙 84개에 어긋나는지 확인한다. 어긋나면 B에게 알리고 REF 문서 §11에 결정을 더한다.
- **비밀 정보**: DB 접속 정보는 `.env`(git 제외)에만 둔다. 형식은 `.env.example`을 따른다.
