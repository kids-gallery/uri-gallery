## 요청 원문

### 배경
- 기존 기준은 "움직일 수 있나 → 움직이면 애니메이션, 못 움직이면 액자"였다. 기준이 모호하고, 감지 모델도 믿기 어렵다. 9/23 시험에서 M3 Animated Drawings가 집 그림을 사람으로 0.946점 판정했다.
- 새 기준(제안, 팀 확정 전)
  - 그림(평면) → 원본 액자가 기본. 움직이게 만들기는 선택 사항이고, M3가 사람 형태를 찾았을 때만 켜진다.
  - 만들기(입체) → 돌려 보기. P0는 사진 여러 장(앞·옆·뒤) 넘겨 보기, P1은 TripoSR 3D("뒷면은 추측해 만든 모습이에요" 안내).
  - 평면·입체는 올릴 때 보호자가 [그림이에요]/[만들기예요]로 정한다. 모델은 시험을 통과했을 때만 "이렇게 보여요" 추천 표시를 붙인다. 미리 선택해 두지 않는다.
- 핵심 질문: **우리가 쓰기로 한 모델이 평면과 입체를, 그리고 그림 속 사람 형태를 실제로 가려낼 수 있는가.** 추측하지 말고 측정으로 답하라.

### 실제 사진에서 확인한 어려운 경우 (시험 세트에 반드시 넣을 것)
1. 평면 위에 입체 재료가 붙은 작품(휴지 뭉치 머리카락, 색종이 모자이크, 스티커)
2. 아이가 손에 들고 찍은 만들기(손가락·몸이 작품과 겹침)
3. 손에 들고 비스듬히 찍은 그림(배경·사람이 넓게 들어감)
4. 활동지 위 그림(인쇄된 밑그림·글자가 섞임)
5. 큰 종이를 바닥에 놓고 위에서 찍은 그림
6. 종이상자·우유갑·병뚜껑 같은 재활용 만들기(바퀴 달린 차, 배)
7. 사람·동물이 없는 그림(집, 지도, 무늬)

### 지킬 것
- **설계서 먼저**: 판정 기준, S2 올리기, S3 확정, 결과 종류, 상태 전이 문서에 수정안을 먼저 쓴다. 팀 확인 전에는 화면 구현을 하지 않는다. 이번 작업은 설계서 수정안과 오프라인 시험까지다.
- **시험 데이터**: 팀원이 직접 그리고 만든 것만 쓴다. 실제 아이 사진, 아이 작품, 인터넷 그림, 얼굴·이름·주소가 보이는 사진은 쓰지 않는다. 손에 든 사진은 손만 나오게 찍는다. 시험 사진은 저장소에 커밋하지 말고 팀 서버의 비공개 경로에 두고, 경로만 기록한다.
- **모델**: 공개 서버에서 활성화하지 않는다. 팀 서버나 로컬에서 오프라인으로만 돌린다. M2는 라이선스 보류 권고 상태이므로 결과가 좋아도 "사용 가능"으로 적지 말고 "라이선스 확정 대기"로 적는다.
- **공정한 측정**: 임계값과 문장(프롬프트)은 **조정용 세트**에서만 고르고, 성능은 따로 떼어 둔 **검증용 세트**로 한 번만 잰다. 검증 세트를 보고 값을 다시 고치지 않는다. 결과가 나쁘면 나쁜 대로 보고한다.

### 할 일 (순서대로)

#### 1. 조사
- 현재 설계서에서 "판정·배정·움직일 수 있나"가 적힌 곳(파일:줄)
- M1·M2·M3·M5·M7이 어느 서버·장치(Studio-B MPS 등)에서 돌 수 있는지, 지금 실제로 설치·실행되는지(명령과 출력으로)

#### 2. 설계서 수정안
- 판정 흐름: 올리기 → 보호자 [그림이에요]/[만들기예요] → 종류별 결과 선택지 → 확정
- 종류별 결과: 그림(액자 기본 / 움직이기 선택 / 2.5D 선택 여부는 팀 결정) · 만들기(여러 장 넘겨 보기 P0 / 3D P1)
- 만들기 촬영 안내 문구 초안: 탁자 위에 놓고 찍기, 앞·옆·뒤 3장, 손·얼굴이 나오지 않게(해요체, 40자 이내)
- 모델이 없거나 실패할 때의 경로: 항상 보호자 선택 + 액자·사진 넘겨 보기로 끝까지 간다
- 바뀌는 데이터: 작품 종류 필드(값: drawing / craft 등 [추론], 기존 스키마와 맞출 것), 만들기의 사진 여러 장 저장 방식
- 이번에 하지 않을 것

#### 3. 시험 세트 설계 (안내만, 촬영은 팀원이 한다)
- 목표 약 60장: 그림 30(사람 있음 12 · 사람 없음 12 · 평면+입체 섞임 6) · 만들기 30(탁자 위 15 · 손에 든 것 10 · 여러 조각 5)
- 위 "어려운 경우" 1~7이 각각 3장 이상 들어가게 한다
- 조정 세트 : 검증 세트 = 1 : 2로 나누고, 사람마다 골고루 나눈다(한 사람 사진이 한쪽에 몰리지 않게)
- 정답표 CSV: 파일명, 촬영자, 정답 종류(평면/입체/섞임), 사람 형태 있음 여부, 어려운 경우 번호, 촬영 조건
- 파일 이름 규칙을 제안한다(예: `t2-craft-hand-03.jpg`)

#### 4. 시험 방법 (모델마다 따로 잰다)
| 시험 | 방법 | 보고할 값 |
|---|---|---|
| A. 평면/입체 — M2 문장 비교 | 문장 후보 3~5쌍("a child's drawing on paper" 대 "a handmade 3D craft object" 등). 조정 세트에서 문장·임계값을 고른다 | 검증 세트의 정답률, 혼동표, "섞임" 사진의 분포, 사진 한 장 처리 시간 |
| B. 평면/입체 — M1 분리 + M5 깊이 | 작품 영역만 잘라 깊이의 평평함(평면 맞춤 잔차 등)을 계산한다 | 같은 항목. 사진 전체 깊이와 잘라 낸 뒤 깊이를 비교 |
| C. 사람 형태 — M3 감지기 | 사람 있음 / 없음 그림에 점수 | 사람 없는 그림에서 잘못 잡은 비율(집 0.946 사례 재현 여부), 임계값별 표 |
| D. 만들기 3D — M7(P1, 가능하면) | 탁자 위 / 손에 든 사진 각 3장 | 결과 캡처, 손가락이 조각에 붙는지, 처리 시간·메모리 |
- 모든 수치에 장치·모델 버전·가중치 이름·실행 명령을 붙인다
- 틀린 사진은 파일명과 이유([추론] 표시)를 표로 남긴다

#### 5. 통과 기준 (초안, 팀이 확정)
- 평면/입체 추천 표시를 켜는 조건: 검증 세트 정답률 90% 이상, 그리고 "만들기를 그림으로" 잘못 본 경우 5% 이하. 못 미치면 보호자 선택만 쓴다.
- 움직이기 버튼을 켜는 조건: 사람 없는 그림을 사람으로 잘못 잡는 비율이 10% 이하가 되는 임계값이 있을 것. 없으면 움직이기는 보호자 [네]/[아니요] 확인 뒤에만 켠다.
- 기준에 못 미쳐도 서비스 흐름은 바뀌지 않는다(보호자 선택이 기본이다).

#### 6. 결과 문서
- 설계서 옆에 `평가_평면입체판정.md` [추론: 기존 평가 문서가 있으면 그 안에 절로 추가]를 둔다. 목적 → 시험 세트 → 방법 → 결과 표 → 틀린 사례 → 결론(켠다 / 끈다 / 보류) → 남은 일 순서로 쓴다.
- 시험 코드는 한 번 실행으로 재현되게 스크립트로 남긴다. 사진 경로·임계값은 코드에 박지 말고 설정 파일에서 읽는다.
