# 모델 임시 활성 기록 (D27, 2026-09-29)

> 지시: 이진우(D) — "모델들을 일단 서비스에 적용시켜라" · 근거 결정: REF §11 **D27** (BR-MDL-03·G22의 예외)
> 대상: 팀 DB `ABC10pioneer1`의 `model_version` 4행 · 서비스: p1.sumzip.com(팀 시험용)

## 왜 예외인가

정식 경로는 평가 묶음 전체 통과 → 평가 담당 판단 → 승격(`release_event`)이다(BR-MDL-03, G22). 평가 항목이 0개라 이 경로를 밟을 수 없어, 팀 시험을 위해 평가 없이 켠다. 평가 근거 없는 승격은 트리거(`trg_release_event_bi`)가 막으므로 **승격 기록은 남지 않는다** — 이 문서가 기록이다.

## 켠 것

| 모델 | 버전 ID | 버전 | 라이선스 | 해시 | 장치 |
|:--:|--:|---|:-:|:-:|---|
| M1 BiRefNet | 5 | M1-e2bf8e4-u4 | 확인 | 있음 | CPU |
| M2 OpenCLIP | 8 | M2-1a25a44-u4 | 확인(보류 해제 `4a9e2e1`) | 있음 | GPU(MPS) |
| M3 Animated Drawings | 6 | M3-b859684-u4 | 확인(내부망 격리) | 있음 | CPU + TorchServe(127.0.0.1) |
| M5 Depth Anything V2 Small | 7 | M5-5426e4f-u4 | 확인(Small만) | 있음 | GPU(MPS) |

켜지 않은 것: M6(P0.5 — 라이선스 팀 확정 전, 설명 패키지 T127 미완), M7(P1 — 어댑터 T131 없음, 라이선스 팀 확정 전).

## 적용한 SQL

```sql
UPDATE model_version SET release_state = 'active'
 WHERE version_id IN (5, 6, 7, 8) AND release_state = 'candidate' AND license_confirmed = TRUE;
```

워커는 활성 버전을 주기적으로 다시 읽어 스스로 모델을 올린다(`workers/runner.py`) — 재시작하지 않는다.

## 되돌리기

```sql
UPDATE model_version SET release_state = 'candidate' WHERE version_id IN (5, 6, 7, 8) AND release_state = 'active';
```

한 모델만 끄려면 S11의 [비활성화](사유 필수, `release_event.kind='deactivate'` 기록)를 쓴다. 이 경우 그 버전은 `retired`가 되므로 다시 켤 때는 새 후보를 등록해 평가한다.

## 조건과 다음 할 일

1. 실제 가족 사용 전, 팀 시험 계정에서만 쓴다.
2. 평가 묶음 1차 12장(`docs/D/D_평가그림_1차_모으기.md`, T164)이 모이면 곧바로 정식 평가한다. 통과하면 승격 기록을 남기고, 미달이면 비활성화한다.
3. M2는 모델 카드의 배포 권고(`docs/A/A_모델_라이선스_확정.md` §2)가 있으므로 판정 제안의 오인을 평가에서 따로 본다. 제안은 보호자가 확정하는 구조라(FR-3) 오인이 있어도 보호자가 바로잡는다.
