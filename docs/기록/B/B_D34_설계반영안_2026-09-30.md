# D34 "올리면 원본 액자로 바로 전시" — 설계 반영안 (B · 2026-09-30)

> 결정: REF **D34**(이제민, 커밋 6bd18e5) · 근거: [`docs/공통/고객요구_올리면걸리는미술관_2026-09-30.md`](../공통/고객요구_올리면걸리는미술관_2026-09-30.md).
> 이 문서가 D34 반영의 **단일 정본**이다. 각 설계서는 이 문서의 해당 절을 옮긴다. 작성: 이제민 세션2(B 몫).

## 0. 한 줄 요약

**"걸려 있는 결과"를 처리 상태와 떼어 낸다.**
- `artwork.hung_result_id`가 전시의 기준이다. 올리는 순간 원본 액자 결과를 만들어 여기에 건다.
- `artwork.status`는 지금처럼 판정 · 권유 · 다시 만들기의 진행만 나타낸다.
- 그래서 걸린 뒤 "움직이게"를 골라 처리 중이 되어도 전시에서 빠지지 않는다. 승인하면 그 결과로 바꿔 건다.

## 1. 지금 규칙과 막히는 점 (확인한 사실)

| 항목 | 지금 | D34와 부딪히는 곳 |
|---|---|---|
| 전시 판정 | 뷰 `v_exhibit_gate`: `status='approved' AND story_complete(제목 · 그린 날 · 나이 모두)` | 올리자마자 전시하려면 승인 · 나이가 없어도 돼야 한다 |
| 원본 액자 | 확정(frame) → `frame_compose` 작업 → `awaiting_review` → 좋아요로 `approved` | 승인 단계가 있다 |
| 다시 만들기 | 확정은 `received · judging · awaiting_confirm`에서만 된다 | 걸린 뒤(approved) 권유 수락 경로가 없다 |
| 나이 | `child`에 생일이 없다. 근거는 `story.age_at_creation`뿐 | "가장 최근 나이" = 그 아이의 가장 최근 이야기 |
| 그린 날 | 서버는 EXIF를 읽지 않는다. 브라우저는 회전에만 쓰고 보내지 않는다(D32) | 촬영일을 따로 보내야 한다 |

## 2. 데이터 (SD_03 · DDL · data-model)

`artwork`에 칸 두 개를 더하고, `story`에 칸 하나를 더한다.

```sql
ALTER TABLE artwork
  ADD COLUMN hung_result_id BIGINT NULL COMMENT 'D34 지금 전시에 걸린 결과(NULL = 안 걸림)',
  ADD COLUMN hung_at DATETIME(3) NULL COMMENT 'D34 처음 걸린 때(UTC)',
  ADD CONSTRAINT fk_artwork_hung FOREIGN KEY (hung_result_id) REFERENCES result(result_id);
ALTER TABLE story
  ADD COLUMN title_auto BOOLEAN NOT NULL DEFAULT FALSE COMMENT 'D34 제목이 "제목 없는 그림 N"으로 자동으로 붙음';
```

- 원본 액자는 지금처럼 `result(result_kind='frame', object_id=NULL)` 행이다(파일 없음, BR-PRC-01). 올리기 트랜잭션에서 **작업 없이 바로** 이 행을 만든다. 이 행은 `stage_job`을 거치지 않으므로 `job_id`를 NULL로 둔다. 그래서 `result.job_id`가 NULL을 허용하는지 확인하고, 막혀 있으면 NULL을 허용하도록 바꾼다.
- `hung_result_id`는 같은 작품의 결과만 가리킨다. 트리거 `trg_artwork_hung_bu`로 `result.artwork_id = artwork.artwork_id`를 검사한다.

**전시 판정(G12 개정) — 단일 지점 유지**

```sql
CREATE OR REPLACE VIEW v_story_complete AS            -- 이름 유지, 뜻 개정: 전시에 필요한 것만
SELECT s.artwork_id, (s.title IS NOT NULL AND s.made_on IS NOT NULL) AS story_complete FROM story s;
CREATE OR REPLACE VIEW v_exhibit_gate AS
SELECT a.artwork_id,
       (a.hung_result_id IS NOT NULL) AS cond_hung,
       COALESCE(c.story_complete, FALSE) AS cond_story,
       (a.hung_result_id IS NOT NULL AND a.status <> 'deleting' AND COALESCE(c.story_complete, FALSE)) AS exhibitable
  FROM artwork a LEFT JOIN v_story_complete c ON c.artwork_id = a.artwork_id;
```

- 나이(`age_at_creation`)는 전시 조건에서 빠진다. 없으면 `v_gallery.age_group = NULL` → 화면 "나이 미정" 구역.
- `v_gallery`는 `v_current_result` 대신 **`hung_result_id`의 결과**를 보인다. 3D 노출이 꺼져 있으면 액자로 보이는 규칙(D10)은 그대로다.
- `v_artwork_display.display_status`(구현 때 다듬음): 걸린 채 **다시 만드는 중 · 확인 대기 · 실패**(`processing` · `awaiting_review` · `failed`)면 그 진행을 보이고(C1 레일), 아니면 걸렸을 때 `'exhibited'`. 걸림 여부는 `exhibitable` → API `exhibited`로 따로 준다. 화면은 "전시 중 · 움직이게 만드는 중"처럼 둘을 함께 보인다(§5).
- 트리거 `trg_story_bu`(걸린 작품의 필수 칸 지우기 금지): 조건 `status='approved' AND 3칸`을 `hung_result_id IS NOT NULL AND (title, made_on)`으로 바꾼다. 나이는 지울 수 있다.
- **옮기기(migration 00xx_d34_hung)**
  - 이미 `approved`인 작품: `hung_result_id` = 지금의 결과(`v_current_result`). frame 결정이면 frame 결과 행을 찾거나 만든다. `hung_at` = `approved_at`으로 채운다.
  - 이야기가 덜 찬 작품: 지금처럼 비전시다. 다만 나이만 빈 작품은 이번 개정으로 전시된다. 제목 · 그린 날은 자동으로 채우지 않는다(보호자가 비워 둔 기록을 존중) `[추론]`.

## 3. 상태 · 흐름 (SD_01 · UC_02~06)

1. **올리기** `POST /v1/artworks` 한 트랜잭션:
   1. 원본을 저장한다.
   2. `result(frame)`을 만든다.
   3. `artwork.hung_result_id` = 그 결과, `hung_at` = 지금.
   4. `story`를 자동으로 채운다(§4).
   5. 판정 작업(split · judge)은 **지금처럼 큐에 넣는다.** 목적은 권유다.

   → 응답 뒤 바로 전시된다. 올리기부터 전시까지 보호자 조작은 1번(+ 선택 자르기)이다.
2. **권유**: 판정이 끝나면 `status = awaiting_confirm`(지금과 같다). 화면은 이 상태를 "이렇게도 만들어 볼까요?"로 보인다. 제안 · 기본 선택 없음(U10) 원칙은 그대로다.
   - 권유를 무시하면 계속 `awaiting_confirm`에 머물고, 작품은 계속 전시된다.
   - **확정 허용 상태에 `approved`를 더한다**(걸린 뒤 다시 만들기, 한 번 승인한 뒤에도 가능). 확정 종류가 frame이면 이미 걸려 있으므로 할 일이 없다(`status → approved`).
3. **다시 만들기**: 확정(animated · relief · sculpture) → `processing` → `awaiting_review`. 이 동안 `hung_result_id`는 그대로라 **액자로 계속 전시된다.**
4. **결과 확인**:
   - 좋아요 → `status = approved`, `approved_at`, **`hung_result_id` = 새 결과**(바꿔 걸기).
   - 다시 찍기 · 실패 처리 · frame 결정은 지금과 같다. frame 결정이면 `hung_result_id`는 원본 액자 그대로다.
5. **승인(BR-APR-01 개정)**: "모델이 만든 결과는 보호자 승인 전 비전시". 원본 액자는 모델이 없으므로 승인 없이 건다.

## 4. 이야기 자동 채우기 (올리기 때 서버가)

| 칸 | 값 | 근거 |
|---|---|---|
| `made_on` | 요청의 `capturedOn`(브라우저가 EXIF `DateTimeOriginal`을 **자르기 전에** 읽어 날짜만 보냄. 위치 · 기기 정보는 보내지 않음). 없거나 미래면 올린 날(KST) | D34 ③ · D32(EXIF 비전송 원칙 유지 — 날짜 하나만) |
| `age_at_creation` | 같은 아이의 이야기 중 `made_on`이 가장 늦은 것의 나이. 없으면 NULL("나이 미정") | 생일 칸 없음(개인정보 최소화) |
| `title` | `제목 없는 그림 {N}` — N은 그 아이의 `title_auto` 작품 수 + 1. `title_auto = TRUE` | D34 ③ |
| `utterance` · `guardian_note` | 비움(선택) | BR-STY-01 · 04 |

보호자가 제목을 고치면 `title_auto = FALSE`가 된다. 화면은 `title_auto`인 작품에 "제목을 붙여 줄까요?"를 조용히 권한다(강요 없음).

## 5. API (openapi — `contracts/`와 `.specify/.../contracts/` 둘 다, CI diff 동기)

- `POST /v1/artworks`
  - multipart에 선택 필드 `capturedOn`(date, `YYYY-MM-DD`)을 더한다. 형식이 틀리면 422 `invalid_param`이고, 미래 날짜는 무시하고 올린 날을 쓴다.
  - 202 응답(기존 코드 유지)에 `exhibited: true` · `hungResultKind: frame` · `story{title, titleAuto, madeOn, ageAtMaking}`이 담긴다.
- `Artwork` 스키마에 `hungResultKind`(frame · animated · relief · sculpture | null)와 `titleAuto`를 더한다. `displayStatus`의 뜻은 §2를 따른다.
- `POST /v1/artworks/{id}/confirm`: 허용 상태에 `approved`를 더한다.
- `POST /v1/artworks/{id}/decision`(like): 성공하면 걸린 결과를 새 결과로 바꾼다고 설명을 고친다.
- `GET /v1/gallery`: 묶음의 `ageAtMaking`은 null을 허용한다("나이 미정"). 항목에 `titleAuto`를 더한다.
- 보호자 화면용 단계(표시 전용, API 값 아님): "올리는 중"(전송 중) → "액자에 담는 중"(202 받기 전 연출) → "걸었어요"(202). 내부 상태 이름은 화면에 쓰지 않는다(D34 ④).

## 7. 시험

- API:
  - 올리기 201 뒤 바로 `GET /v1/gallery`에 나온다(frame, 제목 "제목 없는 그림 1", 나이 = 직전 기록).
  - 걸린 작품을 animated로 확정하면 처리 중에도 gallery에 액자로 남는다.
  - 좋아요를 누르면 gallery가 animated로 바뀐다.
  - `capturedOn`이 미래면 올린 날을 쓴다.
  - 걸린 작품의 제목 · 그린 날을 지우면 422이고, 나이 지우기는 허용한다.
- DB:
  - `hung_result_id`가 다른 작품의 결과를 가리키면 트리거가 막는다.
  - 옮기기 뒤 기존 approved 작품이 그대로 전시되는지 본다(수 비교).
- E2E(390 · 1440): 사진 고르기 1번 → "걸었어요" → 전시에 보임. 화면에 G번호 · 상태 코드가 0건인지 본다.
