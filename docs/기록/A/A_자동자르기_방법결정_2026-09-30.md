# D35 자동 자르기 · 원근 펴기 — 방법 결정과 시험 (A 몫, 2026-09-30)

> 작성: 이제민 세션2가 A 최호준 역할을 이어받아 진행했다(이제민 지시). 결정 근거: REF D35 ⑤ "찾는 방법과 실패 기준은 A가 정한다".
> 코드 · 시험: [`docs/기록/A/autocrop/`](autocrop/) — `autocrop.js`(알고리즘) · `harness.html`(시험 화면) · `make_tests.py`(합성 시험 사진) · `test/`(10장 + 정답 모서리) · `시험결과_합성10장.jpg`

## 1. 결론

- **브라우저에서 직접 계산한다.** 새 라이브러리 · 모델 · 서버 변경은 없다.
- 합성 책상 사진 10장 중 **8장을 자동으로 맞게 잘랐다.**
  - 모서리 오차: 사진 대각선의 **1% 이내**(0.75~0.97%)
  - 걸린 시간: 찾기 약 0.1초, 펴기 약 0.03초(1600px, 노트북 Chrome)
- 나머지 2장은 **틀리게 자르지 않았다.**
  - 손가림: 확신이 낮다고 판정하고, 추정 모서리를 [자르기 고치기]의 시작점으로 넘긴다.
  - 작게 찍힘: 처음엔 틀렸지만 고친 뒤 자동으로 맞췄다(겹침 0.84).
- 원칙: **틀린 자르기보다 안 자르는 게 낫다.** 확신이 기준(0.9)보다 낮으면 자동으로 적용하지 않는다.

## 2. 방법 비교

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **① 브라우저 직접 계산(채택)** | 사진이 서버에 가기 전에 자른다. 잘려 나간 배경(교실 · 아이 얼굴)이 서버에 오지 않는다(D32 ② 원칙과 같다). 의존성이 없고 오프라인에서도 된다. 0.1초 | 사람 손에 든 작품 · 입체 작품은 못 한다 | 평면 종이 그림(대부분의 올리기)에 충분 |
| ② 서버 M1(BiRefNet) 마스크 | 모델 품질 | M1은 종이가 아니라 **그림 선만** 분리한다(선 그림 IoU 0.414, `docs/기록/D/M1_BiRefNet_시험기록.md`). 7~12초, 모델이 꺼져 있으면 불가. 배경이 서버에 온다 | 종이 찾기에 맞지 않음 |
| ③ OpenCV.js | 검증된 함수 | 약 8MB — 휴대폰 데이터에 너무 크다(고객 요구 "휴대폰 데이터로도 빨리") | 제외 |

## 3. 알고리즘 (`autocrop.js`, 약 200줄)

1. 사진을 한 변 320px로 줄이고 두 번 흐린다.
2. 사진 테두리 띠(4%)의 가운데 색을 배경으로 본다. 종이 후보를 세 가지로 만든다.
   - 배경과 다른 곳(오츠 문턱)
   - 그 반대: 종이가 테두리를 덮은 사진용
   - 밝은 곳: 나뭇결처럼 배경 무늬가 셀 때
3. 후보마다 다음 순서로 처리한다.
   1. 닫기 연산을 하고 구멍을 메운 뒤 가장 큰 덩어리를 고른다.
   2. **종이 색으로 다시 거른다.** 덩어리의 가운데 색에서 먼 곳(손 · 옆 물건)을 빼고, 다시 구멍을 메운다.
   3. 테두리 점으로 볼록 껍질을 만들고, 그 안에서 넓이가 가장 큰 사각형을 고른다.
   4. **네 변에 직선을 다시 맞춘다.** 먼 점을 두 번 버린 뒤 이웃 직선의 교점을 모서리로 삼는다. 가려진 모서리를 되찾기 위한 단계다.
   5. 점수를 매긴다. 점수 = min(채움 비율, 테두리 점이 네 변에 붙은 비율)이고, 각이 45~135°를 벗어나면 절반으로 깎는다. 사진의 3%보다 작으면 깎고, 사진 전체와 같으면 0으로 본다.
4. 점수가 가장 높은 후보가 **0.9 이상**이면 자동으로 적용한다. 낮으면 `quad: null` + `guess`(추정 모서리)를 돌려준다.
5. 펴기(`warpQuad`): 네 모서리를 직사각형으로 옮기는 호모그래피를 쓴다. 결과 크기는 마주 보는 변 중 긴 쪽이고, 한 변 최대 2400px이다.

## 4. 시험 (합성 사진 10장 — 실제 아동 그림 · 얼굴 없음, G20)

`design/샘플/export1` 사진은 실제 아이 얼굴이 찍혀 있어 시험에 쓰지 않았다(A 검토 `A_샘플_평가묶음_적합성검토.md`). 대신 책상 · 카펫 위에 크레용 그림 종이를 원근으로 놓은 사진을 만들고 정답 모서리를 기록했다(`make_tests.py`).

| 사진 | 결과 | 확신 | 겹침(IoU) | 모서리 오차 |
|---|---|---:|---:|---:|
| 01 반듯 | 자동 | 1.00 | 0.939 | 0.88% |
| 02 기울기 15° | 자동 | 1.00 | 0.931 | 0.85% |
| 03 강한 원근 | 자동 | 1.00 | 0.934 | 0.97% |
| 04 어두운 조명(한쪽 어둠) | 자동 | 1.00 | 0.950 | 0.75% |
| 05 손이 모서리를 가림 | **고쳐 주세요**(추정 넘김) | 0.86 | 0.871 | 8.56% |
| 06 색종이 · 회색 카펫 | 자동 | 1.00 | 0.935 | 0.81% |
| 07 종이가 사진 밖으로 나감 | 자동(보이는 만큼) | 1.00 | 0.961 | 0.87% |
| 08 작게 찍힘(사진의 6%) | 자동 | 1.00 | 0.839 | 0.85% |
| 09 흰 책상(대비 약함) | 자동 | 1.00 | 0.945 | 0.82% |
| 10 세로 종이 | 자동 | 1.00 | 0.919 | 0.87% |

- 겹침이 0.92~0.96에 머무는 것은 시험 화면이 겹침을 300px 격자로 재기 때문이다(모서리 오차는 1% 이내). 모서리 오차가 기준이다.
- 고친 문제 3개:
  - 손 자국에 변 직선이 끌려감 → 변을 다시 맞출 때 먼 점을 버리고, 점수에 "변에 붙은 비율"을 넣었다.
  - 나뭇결 위의 작은 종이를 못 찾음 → 밝기 후보를 더하고, 사진 전체 후보는 자동 선택에서 뺐다.
  - 확신이 낮을 때의 추정 모서리를 축소 좌표로 돌려주던 버그를 고쳤다.

## 5. 실패 기준 (자동으로 적용하지 않는 때)

| 경우 | 화면 |
|---|---|
| 확신 < 0.9 (손 · 물건이 종이를 가림, 종이 모양이 네모가 아님, 배경과 종이 색이 같음) | 추정 모서리를 [자르기 고치기]에 미리 놓고 "모서리를 맞춰 주세요" |
| 종이가 사진의 3% 미만 | 추정을 넘기고 "가까이서 다시 찍으면 더 선명해요" `[추론]` |
| 네모 종이가 아님(입체 · 손에 든 작품) | 자동 자르기 없음 — D32 사각형 자르기(사진 전체) 그대로 |
| 브라우저가 열지 못하는 사진(일부 HEIC) | D32 ⑥과 같이 자르기 없이 올림 |

## 6. 설계서 반영 초안 (D32 커밋 뒤에 넣는다)

지금 main 작업 트리에 D32 미커밋 변경(REF · spec · UC_02 · SD_01 · SD_02 · UploadView.vue)이 있다. 같은 줄을 건드리므로 **D32가 커밋된 뒤** 아래를 반영한다.

- **spec**: Out of Scope의 "촬영 보정(원근 보정 · 작품 영역 자동 자르기)"를 뺀다. FR-2에 "평면 종이 그림은 올리기 전에 브라우저가 종이를 찾아 반듯하게 편다. 확신이 없으면 보호자가 네 모서리를 맞춘다"를 더한다.
- **UC_02**: BF에 자동 자르기 단계를 넣고, A(대안 흐름)에 [자르기 고치기] 네 모서리 끌기를 넣고, E(예외)에 §5 실패 기준을 넣는다.
- **SD_02 S2**: D32 사각형 → **네 모서리(사각형이 아닌 볼록 사각형)**. 핸들은 모서리 4개이고 키보드로도 움직인다(D32 방식 그대로). 자동으로 찾았으면 편 판을 미리보기로 보인다. [원래대로]로 사진 전체로 돌아간다.
- **D32 ⑤ 개정**: "사각형만 — 회전 · 자유 모양 없음"을 "네 모서리(원근 펴기)"로 바꾼다.
- **원본 정의(BR-INT-04 · D32 ③)**: 편 판을 올리면 편 판이 원본이다. D35 ④ "편 판 별도 객체"는 **전시 뒤 고치기**에만 필요하다. 이때 서버에는 원본만 있으므로, 서버 쪽 다시 펴기(같은 알고리즘을 Node에서, `detectOnPixels`는 순수 함수라 옮기기 쉽다)와 `stored_object` 종류 `rectified` 추가는 D34(B) 흐름과 함께 정한다 `[추론]`.
- **SD_01 · SD_03**: 올리기 전 처리라 상태 전이 · DB 변경은 없다. 전시 뒤 고치기만 SD_03 `stored_object`(위)에 해당한다.

## 7. 남은 것

- **실제 휴대폰 사진으로 재기**: 팀원이 직접 그린 그림을 팀원 책상에서 찍은 사진으로 잰다(G20 · BR-MDL-04 안에서). 합성 사진은 조명 · 렌즈 왜곡 · 그림자가 단순하다.
- **모바일 속도**: 390px 실기기에서 찾기 · 펴기 시간을 잰다. 1600px 기준 노트북은 0.13초였다.
- **제품 이식**: `web/src/app/upload/autocrop.ts`로 옮기고, 단위 시험(합성 10장 · 정답 모서리 · 오차 < 2%)과 E2E(`us2-crop.spec.ts`에 자동 자르기 · 모서리 고치기)를 더한다. 설계서 반영(§6) 뒤에 한다.
