# 신지현 담당 이슈 작업 기록

이 문서는 우리 아이 미술관 프로젝트에서 신지현이 맡은 작업을 이해하기 쉽게 정리한 개인용 기록입니다. 기준: 2026-11-03 GitHub 확인. 이슈는 할 일이고 PR은 변경 사항을 검토받는 요청입니다. PR 병합 여부는 이후 변경될 수 있습니다.

## 전체 흐름

화면을 실행할 환경을 준비하고 → 보호자가 가입·로그인하고 → 아이를 선택하고 → 작품의 제작 방식과 결과를 정하고 → 개인정보 보호와 설치 절차를 확인합니다.

## 1일차: 실행 환경 준비

### [#17 줄바꿈 설정과 3D 화면 빌드](https://github.com/kids-gallery/uri-gallery/issues/17) — 닫힘

Windows와 리눅스에서 같은 스크립트와 설정 파일을 문제없이 사용하도록 줄바꿈 규칙을 정했습니다. 이미지와 글꼴은 텍스트로 변환하지 않도록 했고, WSL에서 3D 화면 배포본을 만들 수 있는지 확인했습니다.

## 2일차: 화면 배포와 보호자 입장

### [#29 회원가입과 이메일 확인](https://github.com/kids-gallery/uri-gallery/issues/29) — 닫힘

## 3일차: 아이와 작품 결과 선택

### [#36 아이 별칭 등록과 선택](https://github.com/kids-gallery/uri-gallery/issues/36) — PR 리뷰 중

아이가 없으면 별칭으로 등록하고, 여러 명이면 한 명을 골라 그 아이의 작품만 보게 합니다. 사진을 올릴 때도 선택한 아이를 사용합니다.

리뷰에서 아이가 한 명일 때 ‘아이 바꾸기’ 창이 바로 닫혀 둘째를 등록할 수 없는 문제가 발견됐습니다. 처음 입장할 때와 아이를 바꾸러 왔을 때를 구분해 고치고 관련 테스트를 추가했습니다. [PR #81](https://github.com/kids-gallery/uri-gallery/pull/81)에 수정 사항을 올리고 재리뷰를 요청했습니다.

### [#38 모델 권유 확정 창](https://github.com/kids-gallery/uri-gallery/issues/38) — PR 리뷰 중

작품을 어떤 방식으로 만들지 보호자가 고르는 창입니다. 화면 아래 알림을 누르면 열리며, 서버가 허용한 선택지만 누를 수 있고 사용할 수 없는 이유도 표시합니다. 자동 선택과 중복 제출을 막습니다.

다른 곳에서 이미 확정해 충돌이 났을 때 옛 알림이 남던 문제를 리뷰에서 고쳤습니다. 최신 상태를 반영하고 다시 확인합니다. [PR #82](https://github.com/kids-gallery/uri-gallery/pull/82)에 재리뷰를 요청했습니다.

### [#39 결과 결정 창](https://github.com/kids-gallery/uri-gallery/issues/39) — PR 리뷰 중

만들어진 결과를 보고 좋아요, 낮춰서 쓰기, 액자로 걸기, 다시 찍기 중 서버가 허용한 행동을 선택합니다. 움직이는 결과는 재생할 수 있고, 다시 찍을 때 아이 선택을 보존합니다.

리뷰에서 다시 찍은 작품의 옛 결정 알림이 남아 다음 작품을 가리는 문제가 발견돼, 작품 상태를 지우고 목록을 다시 불러오도록 수정했습니다. 연결 오류 → 결과 결정 → 만들기 방식 확정 순으로 알림을 표시하도록 겹침도 정리했습니다. [PR #83](https://github.com/kids-gallery/uri-gallery/pull/83)에 재리뷰를 요청했습니다. 이 PR은 #38의 PR #82를 기반으로 합니다.

**#38과 #39의 차이:** #38은 결과를 만들기 전에 방식을 고르는 단계이고, #39는 만들어진 결과를 보고 어떻게 할지 정하는 단계입니다.

3일차 리뷰 수정 후 #81은 전체 462개, #82와 #83은 각각 453개 테스트와 타입 검사를 통과했습니다. 화면 캡처와 실제 브라우저 재확인은 각 PR의 남은 항목을 확인해야 합니다.

## 작업에서 고른 방법과 이유

- #27에서 컨테이너 주소를 고정하는 대신 Docker DNS를 다시 조회하도록 했습니다. 앱을 다시 띄워 내부 주소가 바뀌어도 입구가 새 주소를 찾도록 하기 위해서입니다.
- #30에서 일시적 연결 장애와 로그인 만료를 구분했습니다. 연결 장애만으로 기존 작품 화면을 지우면 보호자가 불필요하게 로그아웃된 것으로 보일 수 있기 때문입니다.
- #36에서 처음 진입 시 한 아이 자동 선택은 유지하고, 아이를 바꾸는 창에서는 자동 선택을 멈추도록 고쳤습니다. 둘째 아이 등록 경로가 필요하기 때문입니다.
- #44에서 모든 응답을 오프라인 저장하는 대신 허용된 정적 자산만 저장하는 방식을 선택했습니다. 인증과 사진 같은 가족 자료를 오프라인 캐시에서 다시 제공하지 않기 위해서입니다.

## #41 신지현 PC 확인 (2026-11-03)

- 환경: Windows의 WSL Ubuntu 24.04, Docker Desktop, linux/amd64, WSL Linux의 헤드리스 Chromium. Windows 네이티브 브라우저는 확인하지 않았습니다.
- 기준 커밋: `51967c041afa497aeb4a47e2087ed86f1ec7149f`. 가짜 모델, 격리된 Compose 프로젝트와 별도 볼륨을 사용했습니다.
- `up -d --build`: 성공. 가입 → 메일 확인 → 아이 등록 → 합성 사진 업로드(202) → 입체 그림 확정 → 좋아요 → 작품 상세와 갤러리에 해당 작품 표시까지 통과했습니다. 상세는 `exhibited`, `decision=like`, `hungResultKind=relief`였습니다.
- 기동 명령은 56초, 브라우저 흐름은 44초였습니다. 기동부터 화면 흐름 완료까지 단일 연속 측정은 아닙니다.
- `docker stats` 42회 표본에서 7개 컨테이너 동시 합계 최대 400.4 MiB. 개별 최대 표본은 DB 153.9, app-api 93.8, model-api 53.8, worker 37.3, mailpit 32.5, sweeper 22.1, web 19.4 MiB입니다. 서로 다른 시점의 개별 최대치는 합산 최대가 아니며, 표본 사이 순간 최대는 알 수 없습니다.
- 첫 자동화 실행은 브라우저 쿠키의 `localhost`와 API 확인에 쓴 `127.0.0.1`의 출처가 달라 상세 조회가 401이었습니다. 확인 스크립트를 브라우저의 실제 출처로 고쳐 전체 경로를 다시 통과했습니다. 제품 오류로 판정하지 않았습니다.
- worker 중단 후 이어받기는 가짜 모델의 빠른 처리로 이 시험에서 검증하지 않았으며, #41 안내대로 맥의 실제 모델 시험을 기다립니다. 문제 이슈는 만들지 않았습니다.
