## 2. 실행 방법(도커 없이, 이 기기 기준)

준비는 한 번만 한다.

1. DB와 메일 수신함을 깐다.
   - `brew install mariadb mailpit` 뒤 `brew services start mariadb`
   - Mailpit 실행 파일을 `~/.local/bin/mailpit`에 연결한다(E2E 스택과 pm2 구성이 이 경로를 쓴다)
   - DB 하나와 사용자 하나를 만들고, `SET GLOBAL log_bin_trust_function_creators=1`을 켠다(스키마의 트리거 생성에 필요. 재시작하면 다시 켠다)
2. 설정 파일을 만든다.
   - 저장소 루트에서 `.env.example`을 `.env`로 복사한다
   - `DB_*`, 두 비밀값, `APP_BASE_URL`, `MAIL_SMTP_URL=smtp://127.0.0.1:1025`, `STORAGE_ROOT`, `UAM_RUN_DIR`를 채운다
   - `.env`는 저장소에 올리지 않는다
3. 의존성을 깐다.
   - `cd web && npm ci`, `cd api && npm ci && npm run build && npm run db:migrate`
   - 서빙: `serving/README.md` 첫 절대로 `serving/.venv`를 만들고 `requirements.lock`, `requirements-models.lock`을 깐다
   - 모델 가중치는 `models/hf/`에 받는다(`models/README.md`)

띄우기는 매번 한다.

```bash
set -a; . ./.env; set +a
npx pm2 start ops/server/ecosystem.config.cjs --only app-api,model-api,worker-cpu,sweeper
npx pm2 start ~/.local/bin/mailpit --name mailpit --interpreter none -- --smtp 127.0.0.1:1025 --listen 127.0.0.1:8025 --database .data/mailpit.db
cd web && APP_API_URL=http://127.0.0.1:9521 npx vite --port 9613
```

- 화면: `http://127.0.0.1:9613/app/`, 3D 세계: `/app/world`, 받은 메일: `http://127.0.0.1:8025`
- 개발 서버의 3D 세계에는 테스트 계정 입구가 보인다. 끄려면 `VITE_TEST_ENTRY=0`을 주고 띄운다(`web/.env.development`)

## 3. 움직이는 그림 엔진(M3) 설치(맥, 도커 없이)

팀 기록 `docs/A/A_모델재현기록.md` M3절을 따른다. 설치물(약 2.4GB)은 저장소 밖 `~/.local/share/uri-gallery-m3/`에 두고 커밋하지 않는다. 받는 곳과 대조할 값은 아래뿐이다.

| 받는 것 | 출처 | 대조 |
|---|---|---|
| micromamba 2.9.0 | `github.com/mamba-org/micromamba-releases` 릴리스 `2.9.0-0`의 `micromamba-osx-arm64` | 같은 릴리스의 `.sha256` 파일(`ec2a072f…e5be`) |
| conda 패키지 | `serving/conda-m3.lock`에 적힌 conda-forge 주소 | 잠금 파일의 md5(micromamba가 대조) |
| pip 패키지 | `serving/requirements-m3.lock`의 판 | 판 고정(해시 없음) |
| AD 저장소 | `github.com/facebookresearch/AnimatedDrawings` 커밋 `b859684857519c7424da51a0b0862fbd1fd258f4` | 커밋 |
| `.mar` 2개 | 같은 저장소 릴리스 `v0.0.1` | SHA-256 `1a2654c8…abfb`(검출), `40ebdc69…e42f`(자세), 크기 327,104,441B · 374,824,711B |

```bash
X=~/.local/share/uri-gallery-m3; E=$X/venv-m3; P=$E/bin/pip; L=serving/requirements-m3.lock
pick(){ grep -iE "^($1)==" $L | tr '\n' ' '; }
# 1 micromamba(받은 뒤 shasum -a 256 결과를 .sha256과 대조하고 ~/.local/bin/micromamba로 둔다)
~/.local/bin/micromamba create -y -p $E --file serving/conda-m3.lock
# 2 pip — 잠금 파일 머리의 순서대로
$P install $(pick 'torch|torchvision')
$P install $(pick 'openmim|torchserve|mmdet')
$P install $(pick 'Cython')
CFLAGS=-Wno-invalid-specialization CXXFLAGS=-Wno-invalid-specialization MMCV_WITH_OPS=1 $P install --no-build-isolation $(pick 'mmcv-full')
$P install --no-build-isolation "$(grep -E '^xtcocotools' $L)"
$P install $(pick 'mmpose')
$P install -r <(grep -vE '^#|mmcv-full|^xtcocotools' $L | grep .)
# 3 AD 저장소와 .mar
git clone https://github.com/facebookresearch/AnimatedDrawings.git $X/AnimatedDrawings
git -C $X/AnimatedDrawings checkout b859684857519c7424da51a0b0862fbd1fd258f4
$P install -e $X/AnimatedDrawings --no-deps
mkdir -p $X/model-store && cd $X/model-store
for f in drawn_humanoid_detector drawn_humanoid_pose_estimator; do curl -fL -o $f.mar https://github.com/facebookresearch/AnimatedDrawings/releases/download/v0.0.1/$f.mar; done
shasum -a 256 *.mar
```

- 팀 기록과 다른 점 두 가지(2026-10-29 이 맥). 새 Xcode clang이 torch 1.13 헤더를 오류로 막아 mmcv-full 빌드에 `-Wno-invalid-specialization`을 준다. xtcocotools는 빌드 중 Cython을 따로 받다가 겹쳐 실패해, Cython을 먼저 깔고 `--no-build-isolation`으로 깐다. 패키지 판은 바꾸지 않았다.
- `.env`에 `TORCHSERVE_URL=http://127.0.0.1:9561`, `M3_AD_PYTHON=$X/venv-m3/bin/python`, `M3_AD_ROOT=$X/AnimatedDrawings`를 더한다.
- 띄우기(저장소 루트에서):

```bash
X=~/.local/share/uri-gallery-m3; E=$X/venv-m3; mkdir -p $X/run
JAVA_HOME=$E/lib/jvm PATH="$E/bin:$E/lib/jvm/bin:$PATH" npx pm2 start $E/bin/torchserve --name torchserve --interpreter none --cwd $X/run -- \
  --start --foreground --ncs --ts-config $PWD/ops/torchserve/config.properties --model-store $X/model-store \
  --models drawn_humanoid_detector.mar drawn_humanoid_pose_estimator.mar
curl -s http://127.0.0.1:9561/ping    # {"status": "Healthy"}
set -a; . ./.env; set +a; npx pm2 restart worker-cpu model-api --update-env
```

## 6. 게임 요소를 넣는 기준

이 서비스의 본질은 쌓여 가는 아이의 작품을 디지털 미술관에 기록하고, 전시하고, 큐레이션하는 것이다. 게임 요소는 이것을 더 즐겁게 하는 수단이다.

요소 하나를 넣기 전에 다음 질문에 답한다: **"이 요소가 작품의 기록·전시·큐레이션 중 무엇을 더 즐겁게 하는가?"** 답과 근거 설계서 절을 PR에 표로 적는다.

| 넣는 것(예) | 연결되는 본질 |
|---|---|
| 걸어서 작품 앞으로 가기 | 전시 |
| 누르면 작품이 움직임 | 전시 |
| 새 작품이 오면 빈 액자가 채워지는 연출 | 기록 |
| 나이별 전시실이 해마다 늘어남 | 큐레이션 |
| 아이 그림으로 만든 캐릭터 | 기록 |

- 작품과 무관한 점수, 재화, 상점, 미션은 넣지 않는다.
- 요소의 수를 늘리지 않고, 이미 넣은 것을 다듬는다.

| 5 | 도커 | 서비스별 컨테이너 구성, 개발·배포 묶음, 망 분리 | 깨끗한 기기에서 한 명령으로 뜨고 흐름이 한 바퀴 돎 | 8절 안건 4·6 |
| 6 | 배포 | 배포 서버, 이미지 저장소, 움직이는 그림 엔진의 x86 서버 동작과 추론 중 메모리 최대치 | 팀이 정한 서버에서 흐름이 한 바퀴 돎 | 8절 안건 3·4·5 |

- 산사 분석에서 먼저 본 것(참고용, 분석 전): 로딩 화면 한 장, 입력 방식에 따라 바뀌는 조작 안내 한 줄(데스크톱 "바닥 클릭 · 드래그로 둘러보기 · 휠로 확대/축소", 휴대폰 "눌러 이동 · 쓸어 둘러보기 · 두 손가락 확대/축소"), 바닥을 누른 자리에 생기는 둥근 표시, 아래쪽 행동 버튼 두 개. 공개 저장소와 소프트웨어 라이선스는 찾지 못했으니 코드·에셋은 가져오지 않는다.

## 9. 알아 둘 것

- 팀 저장소에는 PR로만 올린다. `main`에 직접 올리지 않는다.
- E2E를 돌리면 `docs/B/카카오로그인_캡처/`의 그림 4장을 시험이 다시 쓴다. 바꿀 뜻이 없으면 커밋 전에 되돌린다.
- 개발용 평가 그림(코드로 그린 사람·집)은 연결 확인용이다. 품질 판단이나 팀 서버 승격에 쓰지 않는다.
- 이 기기의 MariaDB는 13.0.2다. 팀 기준(12.0)과 판이 다르다.
