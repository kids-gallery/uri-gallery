# 아이 작품 사진에서 작품만 따내는 자체 모델 제작 과정

대상: 팀원. 자체 모델이 무엇을 하고 어떻게 만들었는지 처음 보는 사람도 설명할 수 있게 정리한다. 측정 원본과 세부 설계는 모델 담당의 개인 저장소 `모델설계서.md` 9.14~9.20절에 있다.

**지금 상태(2026-11-04 15:40 KST 기준).** 시연 모델은 `own8`이다(이제민 결정). 게이트 결과와 상관없이 쓰기로 했다. 게이트는 2회차까지 미통과로 끝났고, 3회차는 끝까지 돌리지 않았다. 체험 VM 교체는 14:54에 끝났다(6절). `own8`은 아이가 든 사진에서 그림과 교실 만들기, 손·옷 제외가 BiRefNet보다 높게 나왔지만 놓인 입체 만들기는 뒤진다. 실제 아이 사진이 들어가 **시연 전용**이고 서비스에는 쓸 수 없다.

## 1. 풀려는 문제

서비스 입력은 아이가 작품을 들고 찍은 사진이다. 전시에는 작품만 필요하다. 그림은 액자에 걸고 만들기는 받침대에 동상처럼 세운다.

목표는 다섯 가지다. 아래 표의 "지금"이 실제 상태이고, 전부 구현된 것이 아니다.

| 목표 | 지금 | 모델 출력으로 하나 |
|---|---|---|
| 사진에서 작품만 따내기 | 연결 있음. 놓인 입체 만들기가 약함 | 예 |
| 그림과 만들기 구분 | 출력은 있으나 서비스에 미연결, 보호자가 답함 | 출력만 |
| 실제 미술관처럼 사실화 | 색 맞춤과 종이 바탕만 구현 | 아니요, 규칙 |
| 3D와 애니메이션 | 입체는 저장소 기본이 Depth Anything이고 체험 VM은 `own8` 깊이로 동작(6절), 애니메이션(M3)은 가짜 | 자체 깊이를 더 많은 사진으로 확인 |
| 캐릭터 3D와 게임 움직임 | 통째 이동. 부위 재조립 미구현 | 출력만, 움직임은 엔진 |

기존 모델 BiRefNet은 "사진에서 눈에 띄는 것"을 따는 범용 모델이다. 아이와 작품을 같이 따고 무겁다. 분리 한 장에 17~20초(첫 장 29초), worker 메모리 최대 8.65GiB다(맥 arm64, 합성 사진 1600×1200 이하 11장, 각 1회, M1·M2·M5를 함께 올린 worker의 `memory.peak`, [마스터플랜 7절](../../design/PLAN_3인디벨롭_컨테이너협업_우리아이미술관.md#7-각자-남길-작업-기록)). 자체 모델은 이 일에 맞게 작고 빠르게 만들려는 것이다.

## 2. 모델 구조

**U-Net + EfficientNet-B0.** 합성곱 신경망(CNN)이다. 앞부분(인코더)이 사진을 줄여 가며 특징을 뽑고, 뒷부분(디코더)이 다시 펼쳐 픽셀마다 답을 낸다. 파일은 약 23MB다. 처리 시간은 맥 컨테이너 CPU 2개, 입력 448, 1회 예측, 다른 작업과 겹치지 않을 때 장당 0.5~0.8초다(공개 견본 측정). 시연 설정(입력 512, 좌우 평균)은 더 오래 걸리고, 다른 작업과 겹친 값만 있다(3.8~8.8초). 시연 VM 값은 미측정이다. 사전학습 가중치 없이 시작했다. 상업 이용 조건 때문이다.

출력 하나에 여러 일을 맡긴다(26채널).

| 출력 | 쓰는 곳 |
|---|---|
| 작품 전체 마스크 | 작품 따내기 |
| 그림 윤곽 마스크 | 입체, 캐릭터 |
| 그림 또는 만들기 | 전시 방식 구분 |
| 깊이 2채널 | 입체 |
| 부위 7채널, 관절 14채널 | 캐릭터 |

**활성화 함수.** 인코더는 SiLU, 디코더는 ReLU, 출력은 시그모이드다. 시그모이드는 값을 "이 픽셀이 작품일 확률"(0~1)로 바꾸는 맨 끝 층에만 쓴다. 부위는 여럿 중 하나를 고르므로 소프트맥스를 쓴다. 활성화 함수를 바꿔 비교한 적은 없다. 문제가 모델이 못 배우는 데가 아니라 자료 차이에 있었기 때문이다.

## 3. 학습 방법

**손실 함수.** 답이 얼마나 틀렸는지 재는 값이다. 출력마다 다르고, 더한 값을 줄이도록 학습한다.

| 출력 | 손실 | 고른 이유 |
|---|---|---|
| 마스크 | BCE + Dice | BCE는 픽셀마다, Dice는 작은 작품에 강하다 |
| 종류 | BCE | 작품 영역 확률로 가중해 배경에 묻히지 않게 한다 |
| 부위 | 교차 엔트로피 | 여럿 중 하나 고르기 |
| 관절 | 히트맵 BCE(양성 가중 40) | 관절점이 희소해서 |
| 깊이 | L1 + 기울기 + 상관 | 값, 표면 변화, 입체 모양을 함께 맞춘다 |

정답이 없는 표본의 출력은 손실에서 뺀다.

**가중치 갱신.** AdamW를 쓴다. 학습률은 처음 학습 0.001, 이어 학습(파인튜닝) 0.0003이고 코사인 스케줄로 줄인다. 가중치 감쇠는 0.0001이다. 기울기 클리핑은 쓰지 않았다. 학습 곡선에서 발산이 보이지 않았다.

**오버피팅 대응.**

- 한 일: 증강(뒤집기, 밝기, 대비, 색, 틀 흔들기), 합성 자료 대량 생성, 가중치 감쇠, 사진 단위 교차 검증, 곡선을 보고 에폭 결정.
- 안 한 일: Dropout, 라벨 스무딩, 회전 증강.

실제로 겪은 오버피팅은 두 가지다. 합성에 맞춰져 실제 사진에서 떨어진 것과, 같은 평가 사진을 여러 번 봐서 점수가 낙관적이 된 것이다. 두 번째는 새 사진으로 재는 것 말고 해결책이 없다.

**후처리.** 확률이 강한 곳(0.5)에서 시작해 약한 곳까지 잇는다. 약한 기준을 0.03에서 0.2로 올리자 학습 없이 그림 점수가 0.920에서 0.961로 올랐고 옷이 잡히는 비율도 0.478에서 0.296으로 줄었다.

## 4. 판마다 무엇을 바꿨나

| 판 | 바꾼 것 | 결과 | 배운 것 |
|---|---|---|---|
| `own2` | 합성 그림 8,000장으로 처음부터 학습 | 그림 분리는 됨 | 합성만으로 시작할 수 있다 |
| `own3` | 합성 3판으로 이어 학습 | 자른 공개 그림에서 BiRefNet보다 높음(0.723 대 0.619) | 아이가 든 사진을 평가에 넣지 않은 것이 가장 큰 누락이었다 |
| `own5` | 사람 사진 위에 작품을 합성, 정답을 "작품 전체"로 | 사람 포함이 크게 줄었으나 만들기 실패 | 합성 틀을 입력에 맞추면 효과가 크다 |
| `own6` | 윤곽, 종류 출력 추가, 만들기 합성 추가 | 통째 사진의 그림이 깔끔해짐. 실제 만들기 실패 | 밤새 학습했는데 실패했다. 전체 학습 전 실제 사진 점수를 재지 않은 것이 원인이다 |
| `own7` | 재활용 공작 합성, 흰 가구 | 합성은 모두 통과, 실제 만들기는 더 나빠짐 | 합성을 고쳐서는 이 틈이 안 메워진다 |
| `own8` | 실제 물체(Open Images), 실제 예시 사진 학습, 약한 기준 0.2, 입력 512와 좌우 평균 | 교실 만들기 3장 0.549 → 0.877. 2회차까지 게이트 미통과 | 실제 자료가 가장 큰 효과였다. 놓인 입체 만들기는 안 풀렸다 |

## 5. 결과

사진 단위로 빼고 학습한 뒤 그 사진으로 잰 값이다(자른 입력, 어댑터 경로). `own8`은 2회차, 약한 기준 0.2, 입력 512, 좌우 평균이다. IoU는 클수록, 포함 비율은 작을수록 좋다. `own6`, `own3`는 입력 448에 기존 설정으로 잰 값이다.

| 항목 | `own8` | BiRefNet | `own6` | `own3` |
|---|---|---|---|---|
| 그림 12장 | **0.960** | 0.941 | 0.920 | 0.635 |
| 만들기 3장(교실) | **0.877** | 0.836 | 0.549 | 0.571 |
| 만들기 1장(바닥, 손으로 그린 정답) | 0.645 | **0.980** | 0.325 | 0.528 |
| 만들기 4장, 게이트 기준 | 0.819 | **0.872** | | |
| 만들기 피부 포함 | **0.177** | 0.320 | 0.217 | 0.536 |
| 만들기 옷 포함 | **0.068** | 0.224 | | |
| 그림 피부 포함 | **0.068** | 0.506 | 0.264 | 0.696 |
| 그림 옷 포함 | **0.296** | 0.306 | 0.375 | 0.391 |

종류 구분은 2회차에서 뺀 사진 17장을 모두 맞혔다.

**읽을 때 조심할 점.**

- 표본이 작다. 만들기는 4장이고, 게이트를 가른 것은 사실상 1장이다.
- 그림 정답은 종이 사각형이라 네모난 답에 유리하다. 만들기 3장의 정답은 BiRefNet 기반이라 BiRefNet에 유리하다.
- 같은 평가 사진을 여러 번 봤으므로 `own8` 쪽에 낙관 편향이 있다.
- 입력 512와 좌우 평균은 다른 항목을 올렸지만 바닥 만들기를 0.769에서 0.645로 낮췄다.
- 처음 보는 판에 붙인 작품은 약한 기준 0.2에서 0.513(놓침 0.486)이다. 아이 옆 바닥의 블록 1장은 두 모델 모두 약하다(`own8` 1회차 0.187, BiRefNet 0.068).
- 최종 가중치는 평가 사진까지 학습하므로 처음 보는 사진 값이 없다. 최종 파일은 같은 방법을 약 2.6배 더 배운 판이다. 위 표는 최종 파일의 성능이 아니라 같은 방법으로 만든 교차 검증 값이다.

**게이트.** 재기 전에 "그림과 만들기 모두 BiRefNet 이상, 손과 피부는 더 적게"로 정했다. 기준을 낮추지 않았고 만들기에서 **미통과**다. 발표에서 "BiRefNet을 이겼다"고 말하지 않고 항목별로 앞선 것과 뒤진 것을 보여 준다.

## 6. 서비스 연결

2026-11-04 15:40 KST 기준이다. 학습만으로 끝나는 일은 작품 따내기뿐이고, 나머지는 코드가 필요하다.

체험 VM은 14:54에 `own8`로 바꿨다. 재배포 출력의 활성 행은 M1과 M5 모두 가중치 해시 `563bf020b9`, 실행 환경 `torch-2.4.1-cpu`다. 같은 조건의 20명 부하(14:57, 200KB 사진, API 호출, 브라우저 렌더링 없음)는 실패 0건, 전시까지 중앙 33.7초, 최대 49.4초, 서버 메모리 최대 2794MiB, 재시작 0회다. `own3` 때는 중앙 22.5초, 최대 37.3초, 2525MiB였다. 현장 와이파이 값은 아니다. 측정 기록은 마스터플랜 3-5에 있다(#136 병합 전까지는 `feat/135-live-entry` 가지).

| 일 | 지금 | 남은 것 |
|---|---|---|
| 작품 따내기 | 체험 VM의 M1 자리에서 동작(`own8`). 저장소 기본은 `own3` | 놓인 입체 만들기 |
| 그림 또는 만들기 | 보호자가 답함(#121) | 모델 값을 기본 선택으로 잇기 |
| 사실화 | 색 맞춤과 종이 바탕(#123) | 펴기, 조명, 손 자국 메움 |
| 입체 | 만들기만 깊이 입체(#134). 체험 VM의 깊이(M5)도 `own8`이고, 저장소 기본은 Depth Anything. 실제 사진 2장의 입체를 눈으로 봤다(#135 댓글) | 놓인 입체 만들기, 옷과 손이 많은 바닥 사진, 실제 휴대폰에서 확인 |
| 애니메이션 | M3가 가짜 | 실제 모델 |

## 7. 학습 자료와 사용 범위

| 자료 | 사용 |
|---|---|
| 합성 그림, Quick, Draw!(CC BY 4.0), Open Images(CC BY 2.0 표시) | `own7`까지. 상업 이용을 전제로 골랐으나 전문가 확인은 안 함 |
| 얼굴을 뺀 실제 아이 사진 자른 판, 사용자 제공 사진(일부 출처 미확인, 이름표와 얼굴 사진 흐림) | `own8`만. 맥 안에서만 |

- `own8` 가중치는 시연 VM에만 올리고 시연이 끝나면 VM과 함께 지운다.
- 저장소에 실제 사진, 그림별 수치, 가중치를 넣지 않는다.
- 공개 후기 게시판은 눈으로 관찰만 했고 그림을 학습에 쓰지 않았다.

## 8. 실수에서 배운 것

- **평가에 실제 입력을 먼저 넣는다.** 합성과 공개 그림으로만 재서 며칠 동안 문제를 못 봤다.
- **전체 학습 전에 작게 학습하고 실제 점수를 잰다.** `own6`, `own7`을 밤새 돌리고 실패한 뒤에 이 순서를 넣었다.
- **넓이 지표를 믿지 않는다.** 많이 따면 덮음 점수가 오른다. 눈 판단과 정답 대비 IoU로 바꿨다.
- **승인 상태를 먼저 확인한다.** 결정 전 화면을 보고 받침대 입체가 안 된다고 잘못 판단한 적이 있다.

## 9. 다음 할 일(서비스로 갈 때)

1. `own8` 계열은 쓰지 않고, 서면 동의받은 사진과 상업 이용 가능한 자료로 다시 학습한다.
2. 입체 만들기 사진을 모으고, 지금 17장은 학습에 썼으므로 평가 사진을 새로 만든다.
3. 얼굴이 서버로 가지 않도록 기기 안에서 도는 자동 상자를 시험한다(`own3` 기준 브라우저에서 장당 약 0.4초, 맥 측정, 휴대폰 미측정).
4. 활성화 함수, 회전 증강, Dropout을 교차 검증으로 비교한다.
5. 저작권과 아동 개인정보는 전문가 확인을 받는다.
