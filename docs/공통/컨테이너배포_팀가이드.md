# 우리 아이 미술관 컨테이너 배포 팀 가이드(배운 내용을 복습하며 진행하기)

작성 2026-10-28, 고침 2026-10-29(핵심 흐름만 남기도록 줄임). 독자는 팀원 3명이다. 마스터플랜(`design/PLAN_3인디벨롭_컨테이너협업_우리아이미술관.md`)이 무엇을·언제·누가 할지 정한다면, 이 가이드는 그 일에 Linux·Git·Docker 교안의 어떤 내용이 쓰이는지와 무엇으로 됐다고 판단하는지를 정한다. 교안을 옮겨 적지 않는다. 교안은 각자 다시 펴 보고, 이 문서는 "어디에 써먹는가"만 잇는다.

## 1. 함께 복습하며 일하는 방식

| 순서 | 하는 일 | 걸리는 시간 |
|---|---|---|
| ① 같이 보기 | 그날 쓰는 주제를 길잡이(3절 표)가 짧게 다시 설명하고, 이 서비스의 어디에 쓰이는지 보여 준다 | 10분 |
| ② 각자 적용 | 이슈 하나 = 가지 하나 = PR 하나. 자기 역할의 폴더에서 한다 | 반나절 |
| ③ 리뷰에서 설명하기 | 리뷰어는 "왜 이렇게 했는가"를 묻고, 작성자는 배운 원칙으로 답한다. 답하지 못하면 병합하지 않고 같이 다시 본다 | 20분 |

- PR 설명에는 "확인한 명령과 결과(숫자)"를 적는다(마스터플랜 부록 B 양식).
- 막히면 30분 안에 팀 채널에 묻는다. 물을 때는 명령, 결과(오류 문구), 이미 해 본 것을 함께 붙인다.

## 2. 시작할 때 먼저 알아 둘 것

- **가볍게 시작한다.** 가짜 모델(`UAM_FAKE_MODELS=1`)을 켜면 모델 없이 전체 흐름이 돈다(`serving/adapters/fake.py`). 이때는 모델 묶음(PyTorch 등) 없이 기본 잠금(`serving/requirements.lock`)만 깔면 된다. 첫 이미지와 첫 compose는 이 구성으로 만들고, 실제 모델(M1·M2·M5)은 4일차에 맥에서 붙인다.
- **모델 묶음 잠금은 CPU 종류마다 다르다.** x86_64 리눅스는 `serving/requirements-models-linux-x86_64.lock`(PyTorch CPU 전용), 맥과 arm64 리눅스는 `serving/requirements-models.lock`이다. 버전은 같다(`serving/README.md`).
- **메모리를 먼저 본다.** M1(배경 분리)은 추론 중 메모리 8.5GB를 쓴다. 메모리가 작은 PC는 가짜 모델로 돈다.
- **주소는 지금 서버에 맞춰져 있다.** app-api와 model-api는 127.0.0.1에 묶여 있고 그 주소가 코드에 고정돼 있다(`api/src/server.ts` 14행, `serving/model_api/main.py` 8행). 다른 컨테이너에서 부르려면 이 주소를 설정 값으로 바꾸는 것부터 한다(설계서 먼저).
- **설정은 지금 pm2가 넣는다.** 앱과 서빙은 `.env`를 스스로 읽지 않고, 팀 서버의 pm2 설정(`ops/p1/ecosystem.config.cjs`)이 `.env`를 읽어 넣는다. compose에서는 `env_file`이 그 일을 한다.
- **메일은 Mailpit으로 받는다.** 메일을 끄면 이메일 가입도 꺼진다. 가입 확인 메일은 Mailpit 화면(8025)에서 연다.
- **시험은 로컬에서 돌린다.** 지금 CI 파일(`.gitlab-ci.yml`)은 GitHub에서 돌지 않는다. PR 전에 자기 폴더의 시험을 돌리고 결과를 PR에 적는다. 서빙·api 시험은 임시 MariaDB를 스스로 띄우므로, 리눅스에서는 `sudo apt install mariadb-server` 뒤 일반 사용자로 돌린다.

## 3. 주제별 복습과 적용

"교안"은 이번 과정의 Linux·Git·Docker 교안이다. 장 이름은 교안의 큰 제목을 줄여 적었다. 이번 5일에 쓰는 주제만 적었다.

### 3-1. 협업(Git)

| 교안 주제 | 이 서비스에서 할 일 | 손에 익힐 명령 | 됐다고 보는 기준 | 길잡이 |
|---|---|---|---|---|
| Git 원격 | 팀 저장소를 받고 push한다 | `git clone`, `git remote -v`, `git push` | 세 사람 모두 자기 가지를 push했다 | 팀원 B |
| 브랜치·PR·리뷰 | 핸드북 규칙대로 이슈 → 가지 → PR → 리뷰 → 병합 | `git switch -c`, `gh pr create`, `gh pr review` | main 직접 push 0건, 병합된 PR마다 리뷰 1건 이상 | 팀원 B |

모델 가중치는 저장소에 넣지 않는다(`git ls-files models`로 0개 확인).

### 3-2. 리눅스

| 교안 주제 | 이 서비스에서 할 일 | 손에 익힐 명령 | 됐다고 보는 기준 | 길잡이 |
|---|---|---|---|---|
| 프로세스·자원 | 모델 컨테이너의 메모리를 잰다 | `free -h`, `df -h`, `docker stats` | 마스터플랜 7절의 메모리 칸이 실제 값이다 | 이제민 |
| 네트워크 | 어떤 포트가 열려 있는지 본다. 바깥에는 9501·8025만 연다 | `ss -tlnp`, `curl` | 내부 서비스 포트가 호스트에 열려 있지 않다 | 팀원 A |
| 패키지·Python 환경 | 잠금 파일로 같은 버전을 깐다 | `pip install --require-hashes` | 맥과 Windows에서 따로 빌드해도 같은 버전이 깔린다 | 이제민 |

### 3-3. 컨테이너(Docker)

| 교안 주제 | 이 서비스에서 할 일 | 손에 익힐 명령 | 됐다고 보는 기준 | 길잡이 |
|---|---|---|---|---|
| 이미지와 컨테이너 | `python:3.11`·`node:22` 컨테이너에 들어가 지금 서비스를 손으로 깔아 보고, 필요한 것을 적는다 | `docker run -it`, `docker ps`, `docker exec`, `docker logs` | 손으로 깐 순서가 설계 PR에 있다 | 이제민 |
| Dockerfile | 서비스마다 Dockerfile. 잠금 파일을 먼저 복사해 설치하고 소스는 나중에 넣는다. 웹은 빌드 단계와 실행 단계를 나눈다. `.dockerignore` | `docker build`, `docker image ls` | 소스 한 줄만 바꾼 다시 빌드에서 설치 층이 재사용된다 | 각자 자기 이미지 |
| 데이터 | DB 자료와 작품 파일을 볼륨에 둔다 | `docker volume ls`, `docker volume inspect` | `docker compose down` 뒤 다시 띄워도 가족 작품이 남는다 | 팀원 B |
| 네트워크 | 서비스끼리 이름으로 부른다. 환경 값과 비밀을 넘긴다 | compose 네트워크, `ports`, `env_file` | 입구만 바깥에 열려 있다 | 팀원 A |
| Compose | 한 파일로 전체를 띄운다(가짜 모델로 먼저) | `docker compose up -d`, `ps`, `logs`, `down` | 한 명령으로 모든 서비스가 뜬다 | 이제민 |
| Compose 심화 | 상태 확인(`/live`·`/ready`)과 기동 순서, 재시작 | `healthcheck`, `depends_on`의 `service_healthy`, `restart` | DB가 늦게 떠도 api가 죽은 채로 남지 않는다 | 팀원 B |

## 4. 날짜별 순서

마스터플랜 5절과 같다. 그날 쓰는 주제를 아침 10분에 같이 다시 본다.

| 날 | 마스터플랜 | 아침에 함께 복습할 주제 |
|---|---|---|
| 1일차 | 바탕 | Git 원격·브랜치·PR, 이미지와 컨테이너, 프로세스·자원 |
| 2일차 | 이미지 | Dockerfile, 패키지·Python 환경 |
| 3일차 | 묶기 | 데이터, 네트워크, Compose, Compose 심화 |
| 4일차 | 실제 모델·배포 | 리눅스 네트워크(배포 서버 포트 확인) |
| 5일차 | 발표 | 각자 맡은 주제를 발표 형식으로 설명 |

## 5. 하지 않을 것

- 교안 문장이나 교안에 딸린 예제 파일을 이 저장소에 옮겨 붙이기.
- 한 사람이 다른 역할의 이미지를 대신 다 만들어 주기(리뷰와 짝 작업은 좋다).
- 설명할 수 없는 설정을 병합하기(1절 ③의 기준).
- 마스터플랜 10절에서 뺀 일(CI 옮기기, 레지스트리, 모니터링, 장애 리허설, 백업 스크립트, 보안 점검표, GPU 등)을 시간이 남는다고 다시 넣기.
