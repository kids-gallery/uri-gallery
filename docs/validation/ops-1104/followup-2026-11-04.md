Restic 시험은 실제 운영 snapshot 대신 작은 합성 `manifest.json`과 `db.sql`을 사용했다. 이 결과만으로 DB·사진 전체의 암호화 복원이나 RPO 24시간/RTO 1시간을 보장하지 않는다. 평문 snapshot을 만든 뒤 암호화하기 전까지 호스트에 남는 구간도 아직 해소하지 않았다.

이전 버전의 `max-age=300`/`max-age=60` 응답을 이미 브라우저가 보관했다면 배포 직후 잠시 남을 수 있다. 새 응답의 `no-store`와 서버의 공유 해제 404는 확인했지만 실제 모바일 브라우저의 기존 캐시 제거는 별도 시험이 필요하다.

API 회귀 시험 첫 실행은 MariaDB 도구가 없는 이미지로 시작되어 실패했다. 일반 사용자로 MariaDB를 실행한 다음 6개 시험은 통과했으나 Vitest 캐시 디렉터리 권한 오류로 프로세스는 1로 종료했다. `--no-cache`로 재실행한 결과 6개 시험 모두 통과하고 종료 코드 0을 확인했다. API 타입 검사도 통과했다.

Restic 명령은 Docker에서 직접 실행했다. `encrypted-backup.py`는 Python 문법 검사만 완료했으며, 실제 S3 연동과 전체 snapshot 대상 실행은 검증 대기다.
