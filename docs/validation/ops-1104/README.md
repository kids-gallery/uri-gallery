## 실제 수치와 증거

- Node 자동 시험 10개, API 설정/권한/지표/요청 번호 회귀 31개, Python 운영 설정 4개 통과. API 시험 DB는 임시 컨테이너 안의 소켓 MariaDB다. Python은 캐시 폴더 쓰기 권한 경고 2건만 있었고 시험 4개는 통과했다.
- 실제 앱 API 합성 경로 20개 항목, 6.69초. 원본은 워커 재개·서비스 재시작 뒤 같은 SHA-256이었다.
- 로그 probe 12건은 1.649초, Loki 중단 구간의 다음 12건은 17.813초에 조회됐다. 표본 중복 0건이고 Alloy 재시작 뒤 이전 probe는 여전히 12건이었다. 초기 Windows 경로 처리 오류는 검증 스크립트를 수정한 뒤 다시 통과했다.
- snapshot 쓰기 중지/백업 3.53초, 당시 작품 3·파일 14. 복원 30.16초, 백업 후 삭제한 1건을 재적용해 작품 2·파일 9. 세션 0개 → 이전 세션 401 → 재로그인 204 → 삭제 작품 404. 복원본은 외부 포트 없이 메일을 끄고 검증했다.
- 복원 후 살아 있는 합성 작품도 새 계정 로그인으로 원본 200과 fixture SHA-256 일치를 확인했다. 시험 DB 앱 계정의 전역 권한 0개와 root/앱 비밀 값이 다름을 값 노출 없이 확인했다.
- 가짜 split 처리 중 SIGKILL: 72.32초 뒤 두 번째 시도로 done. 원본 체크섬 불변, 작품 1건. 처음 검증은 선택지를 완료로 오인해 실패했으며, 실제 DB 작업 done을 기다리도록 고친 뒤 다시 통과했다.
- 실패 이미지 롤백 7.95초. 작품 4→4·파일 17→17, 이전 이미지 ID와 인증 조회 200 확인. DB 비호환 변경은 넣지 않았다.
- 가짜 모델 유휴 자원 10회 동시 합 최대 표본 312.0MiB. 개별 최대의 합이나 순간 최대가 아니다. 24시간 운영값·실제 모델 메모리로 사용하지 않는다.

`docs/validation/ops-1104/`에는 cookie·비밀·메일 링크·DB dump를 제외한 JSON 및 합성 로그판 캡처만 넣는다. 보관 삭제 실패도 별도 report로 남긴다. 이 기록으로 11개 이슈를 닫지 않는다.
