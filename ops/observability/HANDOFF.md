# 운영 시험 인수인계 (#111·#112)

현재 공개 서버에 적용할 수 있는 완료본이 아니다. 실제 결과와 남은 항목은 `docs/validation/ops-1104/README.md`에 있다.

1. PR 커밋과 `git status --short`를 확인한다. DB 마이그레이션이 있으면 이전 이미지와 호환되는지 별도로 검토한다.
2. README대로 새 시험 비밀과 프로젝트를 만들고 Compose config 검사, Node 자동 시험을 실행한다. 다른 가족/운영 볼륨 이름과 일치하면 기동하지 않는다.
3. 가짜 모델·Mailpit으로 flow-check를 실행한다. 실패 때 요청 내용이나 비밀 대신 명령·환경·기대/실제 상태만 남긴다.
4. 백업 manifest·파일 checksum을 확인한다. 복원은 비어 있는 새 프로젝트에서만 실행한다. 삭제 이력·세션 무효화·메일 금지·외부 포트 금지가 빠지면 공개하지 않는다.
5. 큐/워커 문제는 원본 파일 존재와 체크섬 → 작업 상태·lease → 워커 상태 → 모델 준비 순으로 본다. DB 불가와 실제 큐 적체를 구분한다. 오류를 피하려고 원본이나 작업 행을 임의 삭제하지 않는다.
6. 로그가 없으면 업무가 없었던 것인지 collector heartbeat·Loki 수신·Alloy 위치 파일을 함께 확인한다. #105 합성 보관 시험은 만료 조회 차단과 청크 삭제를 확인했다. 실제 7일 운영은 미검증이다.
7. 실패 이미지는 rollback-check의 순서처럼 이전 이미지 ID로 돌린 뒤 재로그인·작품·파일 개수와 원본을 확인한다. 비호환 DB 변경은 이미지 롤백만으로 되돌릴 수 없다.
8. 검증한 사람, 정확한 커밋/이미지 ID, 설정 파일 이름, 명령, 걸린 시간, 실패·남은 일을 본인 기록으로 남긴다. 이 문서 작성자가 아닌 팀원의 실제 재현 전에는 #111·#112 인수인계를 완료로 보지 않는다.

암호화 저장소의 비밀번호를 잃으면 복원할 수 없다. Restic의 `check --read-data`와 새 폴더 `restore`를 실행한 뒤 평문 snapshot의 manifest/체크섬과 비교한다. 실제 S3 연결·계정 권한·주기 실행·실패 통지는 아직 완료되지 않았다. 복원 대상은 기존 서비스 볼륨이 아닌 새 격리 프로젝트로 제한한다.

## 비용과 확장 기준선

이번 표본은 가짜 모델의 유휴 10회/32.85초다. 24시간 로그 유입량·실제 모델 동시 처리·최대 사용자 수의 값이 아니다. 로그/DB/작품/백업/관측 버퍼 각각의 증가량과 스토리지·컴퓨팅 단가를 받은 뒤 계산한다. 아직 예산이나 금액은 정하지 않았다.

초기 관측 값: 큐 최장 대기 60초 초과 또는 scrape 불가, 워커/DB health 실패 2회 연속, collector heartbeat 30초 초과. 60초는 시험 초기값이고 운영 SLO가 아니다. 실제 모델별 처리 상한과 사용자 대기 시간 표본을 보고 조정한다.
